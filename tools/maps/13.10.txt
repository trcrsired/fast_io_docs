2|第13.10章: friend：放进一个外来者
3|1. 属于类型、却无法作为成员的操作
4|有时你需要的操作接受该类的两个对象并把它们平等对待。两个点的中点、两个点之间的距离、两个向量的和：它们都不是“左手那个对象的方法”，而写在类外面也做不到，因为它需要的数据是私有的。
5|<strong><code>friend</code> 就是类给予某个具名外来者以自身成员函数所拥有的访问权限的方式。</strong>许可在类内部授予，由拥有数据的那个类来授予：
6|<code>friend</code> 那一行是一个普通自由函数的<em>声明</em>，只不过它被允许往里看。它不是成员：它没有 <code>this</code>，不在对象上调用，也不属于类的成员函数列表。
7|2. 友元函数与友元类
8|两种授予，两种形状：
9|<strong><code>friend point midpoint(point const &amp;, point const &amp;)</code></strong> &mdash; 一个自由函数可以读 <code>x_</code> 与 <code>y_</code>，也可以使用公有构造函数。别的什么都不变。
10|<strong><code>friend class inspector;</code></strong> &mdash; <code>inspector</code> 的每个成员函数都可以读它们，包括上面用到的静态 <code>dump</code>。授予的对象是整个类，正如 <code>private</code> 也是授予整个类一样（<a href="/docs/13.class/04.access/">第13.4章</a>）。
11|<strong>为什么 <code>midpoint(a, b)</code> 能被调用。</strong>一个只在类内声明为 <code>friend</code> 的函数对普通名字查找不可见，但当它的某个实参具有该类类型时它会被找到 &mdash; 这就是实参依赖查找，也正是 <code>midpoint(a, b)</code> 不需要在命名空间作用域再声明一次就能解析的原因。如果你希望实参里完全不含该类类型时也能调用它，那就同时在命名空间作用域声明它。
12|3. <code>friend</code> 不是什么
13|人们以为
14|实际发生的是
15|“友谊是双向的。”
16|并非如此。如果 <code>inspector</code> 是 <code>point</code> 的友元，那么 <code>inspector</code> 可以看 <code>point</code> 内部 &mdash; 但 <code>point</code> 什么也没得到，<code>inspector</code> 自己的私有成员对 <code>point</code> 依然是私有的。
17|“我朋友的也是我的朋友。”
18|它不可传递。<code>inspector</code> 是 <code>point</code> 的友元，这并不说明任何别的类。
19|“我可以把自己声明为友元。”
20|不行。只有拥有数据的类才能授予访问权。友谊是给予的，从不被索取。
21|“友元就是成员。”
22|不是。友元函数内部没有 <code>this</code>，它也不列在类的成员函数中。
23|4. 最后才用它
24|<code>friend</code> 是你能在墙上开的最窄的洞，但它仍然是一个洞。授予之前，按这个顺序检查更便宜的做法：
25|<strong>能用成员函数做吗？</strong>如果这个操作有一个自然的主体对象，就把它做成成员。<code>midpoint</code> 没有自然主体 &mdash; 这就是它不作为成员的原因。
26|<strong>能用公有接口做吗？</strong>基于公有访问器（<code>a.x()</code>、<code>a.y()</code>）的友元函数完全不需要授权。当访问器已经存在时就那样做；这能让类保持封闭，也让函数可测试。
27|<strong>它是关于类而不是关于对象的吗？</strong>那就该用静态成员函数（<a href="/docs/13.class/09.staticfunctions/">第13.9章</a>）。
28|<strong>否则</strong> &mdash; 两个对象之间的对称操作是经典情形 &mdash; <code>friend</code> 就是合适的工具。
29|<strong><code>friend</code> 会制造耦合。</strong>友元函数现在成了类实现的一部分：改动数据成员，友元就坏了，尽管它在类里并不显眼。对真正属于该类型接口的两三个操作来说，这是可以接受的；而如果你把友谊发给任何需要走捷径的东西，它就是一个维护陷阱。如果好几个外来者都需要同一份数据，设计问题通常是那份数据该不该有公有访问器 &mdash; 而不是要不要加第五个友元。
30|<strong>运算符也是这样写的。</strong>像 <code>+</code> 或 <code>==</code> 这样接受两个该类对象的运算符，与 <code>midpoint</code> 形状相同，通常也因为同样的理由声明为 <code>friend</code>。运算符会在教程后面、在你手上有了类和引用之后再讲。
