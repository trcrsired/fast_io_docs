3|1. 为什么需要这一章
4|<a href="/docs/13.class/">第13章</a>里的每个类拥有的都是数字。复制一个显然无害：<code>point b{a}</code> 得到两个点，没有任何共享。<code>account</code> 拥有的是一笔余额，复制它同样无害。
5|一旦类拥有由操作系统发放的东西 &mdash; 文件描述符、socket、锁、一块内存 &mdash; 这份安心就结束了。两个对象拥有同一个描述符是一个等着发生的 bug，而编译器的默认行为制造的恰好就是这个 bug：它复制那个数字，而不是复制资源。
6|这样的类必须回答五个问题，本章就是这五个答案。
7|2. 什么是资源
8|<strong>资源</strong>是任何满足下列条件的东西：
9|使用之前必须<strong>获取</strong>，使用之后必须<strong>释放</strong>，
10|只能被获取有限次，
11|由<strong>一个句柄</strong>标识，你传递句柄而不是传递那个东西本身。
12|文件描述符是最小的有用例子。<code>::open</code> 返回一个 <code>int</code>；<code>::close</code> 把它还回去；进程能拥有的数量是有限的；而这个 <code>int</code> 是句柄，不是文件。复制句柄<em>不会</em>复制文件 &mdash; 它给同一个东西起了第二个名字，而一个资源有两个所有者，正是本章要解决的问题。

36|其中五个是编译器会替你生成的特殊成员；<code>swap</code> 不是 &mdash; 除非你写出调用，否则没人会调用它。它仍然属于这里，因为它是唯一一个能让复制赋值变得<em>安全</em>的操作（<a href="/docs/14.fiverules/08.copyandswap/">第14.8章</a>），也因为 <code>::std::swap</code> 会退化成三次移动，而只有你的移动是 <code>noexcept</code> 时它才既快又安全。
37|4. 贯穿全章的示例：<code>my_posix_file</code>
38|从这一页开始的每一页都使用同一个贯穿示例：一个拥有 POSIX 文件描述符的类。它是 fast_io 自己在 <code>basic_posix_file</code> 里所做工作的简化版本，只保留五法则需要的东西，从而让有意思的代码永远不超过十五行。
39|路径是 <code>::fast_io::cstring_view</code>，标志是普通的 POSIX <code>int</code> 标志（<code>O_RDONLY</code>、<code>O_WRONLY | O_CREAT</code> 等），函数体直接调用 <code>::open</code>、<code>::dup</code> 和 <code>::close</code>。没有任何东西藏在 fast_io 的辅助设施后面，所以本章陈述的每一条规则都能对着页面上的代码核对。
40|失败用本教程唯一的报告方式报告（<a href="/docs/03.statements/16.herbceptions/">第3.16章</a>）：
41|在 POSIX 系统上标准的 <code>::std::errc</code> 取值就是 <code>errno</code> 的取值，所以强制转换精确保留了错误；处理者会看到 <code>[posix](2)No such file or directory</code> 之类的内容。
42|5. 为本章付账的两个想法
43|规则本身只是记账。有两个想法让它们值得学，也正是本章存在的理由。
44|那条临界线
45|在一个可能失败的函数内部，存在一条线 &mdash; 有时很明显，有时只是一个语句 &mdash; 使得
46|<strong>在它之上：</strong>允许失败，而还没有任何东西被修改；
47|<strong>在它之下：</strong>不允许失败，修改就在那里发生。
48|把每个可能失败的步骤放到线之上、每个改动放到线之下，这个操作要么完整发生，要么完全不发生。这就是<strong>强异常安全保证</strong>，也正是<a href="/docs/14.fiverules/04.copyassignment/">第14.4章</a>真正要讲的东西。
49|异常安全的四个级别
50|<code>nothrow</code>、<code>strong</code>、<code>basic</code>、<code>none</code> &mdash; 你写的每个函数必然恰好属于其中之一，无论你是否想过这个问题。<a href="/docs/14.fiverules/09.exceptionsafety/">第14.9章</a>为它们命名，对 <code>my_posix_file</code> 的每个成员分类，并说明赫布异常如何把第一级从一句承诺变成编译器能证明的东西。
51|6. 本章使用的约定
52|私有数据成员以下划线结尾：<code>fd_</code>。
53|每个成员函数要么是 <code>noexcept</code>，要么是 <code>throws</code> &mdash; 本教程中不存在第三个选项（<a href="/docs/06.function/16.noexceptthrows/">第6.16章</a>）。它是哪一个，会在你读函数体之前就告诉你异常安全级别。
54|整数用 <code>::std::int_least32_t</code>、<code>::std::int_least64_t</code> 或 <code>::std::size_t</code>，绝不用裸 <code>int</code>。唯一的例外是 <code>int main()</code>，以及 POSIX API 自身的 <code>int</code> 参数和返回值，它们就按 <code>int</code> 展示。
55|失败用赫布异常：<code>throw throws ...</code> 与 <code>catch throws (::std::error e)</code>。
56|这些页面上的每个完整程序都用 <code>-std=c++26 -fherbceptions -lherbceptions</code> 编译并运行过；显示的输出就是它实际打印的内容。
