3|概述
4|<a href="https://www.winehq.org/" target="_blank" rel="noopener noreferrer">Wine</a>（“Wine Is Not an Emulator”）让 Windows 二进制程序能在 Linux、FreeBSD 等 POSIX 系统上运行。Wine 通过把 Win32 与 NT API 翻译成宿主系统调用来实现它们 &mdash; 而那些宿主系统调用最终使用的就是 POSIX 文件描述符。
5|当 <code>fast_io</code> 作为 Wine 自身的一部分构建时（或者用于在 Wine 下运行、需要直接与宿主打交道的代码时），它通过下面这些类型暴露这一层：
6|<code>::fast_io::wine_file</code> &mdash; 对 Wine 宿主文件描述符的 RAII 拥有式包装。
7|<code>::fast_io::wine_io_observer</code> &mdash; 对已有 Wine 宿主文件描述符的非拥有视图。
8|<p> <strong>注意：</strong>上游 <code>fast_io</code> 中的 Wine 层尚未完成。本节描述的是它按计划落地时的设计。不过这些概念与你在 POSIX、Win32、NT 上已经见过的 RAII / observer 模式完全一致。 </p>
9|模式是一样的
10|<code>fast_io</code> 中的每一层都遵循同样的形状：
11|一个名为 <code>xxx_file</code> 的拥有式 RAII 类型。
12|一个名为 <code>xxx_io_observer</code> 的非拥有观察者类型。
13|对 <code>print</code>、<code>println</code> 与 <code>scan</code> 的完整支持。
14|能够包裹来自外部代码的原始句柄。
15|<code>wine_file</code> 也不例外。概念上它长这样：
16|包裹 Wine 宿主文件描述符
17|当 Wine 翻译一次 Windows <code>CreateFileW</code> 调用时，它最终会产生一个宿主 POSIX 文件描述符。你可以把这个描述符包进 <code>wine_io_observer</code>，从而通过 <code>fast_io</code> 继续使用它：
18|为什么需要这一层？
19|Wine 是一套复杂的基础设施。位于 Wine 内部的代码（例如 Wine 自己的 <code>ntdll.dll</code> 或 <code>kernel32.dll</code> 实现）需要：
20|从客户代码那里接收一个 Windows <code>HANDLE</code>。
21|通过 Wine 的内部表把它翻译成宿主 <code>int fd</code>。
22|在那个 <code>fd</code> 上执行宿主 I/O，同时仍能把错误以 NTSTATUS 码的形式呈现给客户。
23|<code>wine_file</code> 让 Wine 开发者获得与其他层一样的 RAII / observer 使用体验，而不必在每个调用点手写资源管理。
24|与其他层的关系
25|在运行 Wine 的 POSIX 宿主上，完整的分层是这样的：
26|客户的 Windows 二进制程序调用 <code>WriteFile</code>，这在 Wine 内部解析为 <code>ntdll!NtWriteFile</code>。
27|Wine 的 <code>ntdll</code> 把它翻译成对宿主 fd 的一次 POSIX <code>write(2)</code> 调用 &mdash; 而 <code>wine_file</code> 包裹的正是这个 fd。
28|因此从客户的角度，I/O 走的是 NT 层；从宿主的角度，走的是 POSIX。<code>wine_file</code> 就住在两者之间的接缝上。
29|小结
30|<code>::fast_io::wine_file</code> 是 Wine 宿主文件描述符的 RAII 包装。
31|<code>::fast_io::wine_io_observer</code> 是非拥有视图。
32|Wine 层仍在开发中，但它的设计与 <code>posix_file</code>、<code>win32_file</code>、<code>nt_file</code> 完全同构。
33|它位于 Windows 客户与 Wine 所运行的 POSIX 宿主之间的边界上。
