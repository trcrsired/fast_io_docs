3|1. 它有什么不同
4|<code>str_swiss_set</code> 与 <code>str_swiss_map</code> 是哈希表。它们计算键的哈希，把元素放进由该哈希选定的槽位，而不是让键保持有序。三个后果决定了你该怎么用它们：
5|<strong>没有顺序。</strong>遍历顺序由哈希决定。对相同输入它是可复现的，但它既不有序，也不是插入顺序。绝不要基于它构建逻辑。
6|<strong>大小是已知的。</strong><code>size()</code> 与 <code>capacity()</code> 既精确又便宜，<code>reserve()</code> 让你能一次把表的大小定下来。
7|<strong>只有键操作。</strong><code>contains</code>、<code>find_key</code>、<code>insert_key</code>、<code>erase_key</code>。没有 <code>lower_bound</code>，没有 <code>front()</code>/<code>back()</code>：那些都需要哈希表并不具备的顺序。
8|注意遍历顺序：既不是有序的，也不是插入顺序。
9|2. <code>size()</code>、<code>capacity()</code>、<code>reserve()</code>
10|哈希表必须知道自己有多满 &mdash; 它就是这样决定何时增长的。所以计数本来就在手边，你免费拿到它：
11|<code>capacity()</code> 与 <code>size()</code> 不是同一个数：表会让一部分槽位保持空闲，使探测保持简短。当表被填满时，它会增长，并把每个键重新哈希进一张更大的表。
12|如果你知道要来多少个键，<code>reserve(n)</code> 可以一次在开头把表扩好，这样后续插入不会反复触发增长：
13|<strong>批量装载之前先 reserve。</strong>读取一个大小未知的文件正是你无法 reserve 的情形 &mdash; 但当你知道大小时（文件头写着“1000 条记录”，或者你已经数过行数），<code>reserve</code> 能把一串“重新哈希并复制”的步骤变成一次分配。
14|3. 插入与删除
15|插入函数返回一个小结构体而不是裸 <code>bool</code>，因为哈希表知道自己碰了哪个槽位，并把迭代器交给你：
16|删除仍然是 B 树容器那套 <code>erase_key</code> / <code>erase(it)</code> / <code>erase(first, last)</code> 家族，边遍历边删除的循环形状也一样（第10.6章）：
17|从哈希表中删除可能把某个元素搬进它留下的空洞，所以你在删除之前保存的任何迭代器或键视图都已经失效（第10.11章）。
18|4. 读写映射值
19|读是 <code>find_key</code>，写是赋值函数。两次调用，两种含义：
20|要就地更新值而不是替换它，就用非 const 的映射做遍历 &mdash; 非 const 迭代器暴露可写的 <code>mapped()</code>：
21|<code>find_key</code> 即使在非 const 映射上也返回 <code>const_iterator</code>，所以 <code>m.find_key(k)-&gt;mapped()</code> 只能读不能写。规则就是这些：查找只读，所有修改要么来自插入/赋值函数，要么来自遍历。
22|哈希器是类型的一部分（默认是 <code>::fast_io::native_swiss_hasher</code>）。你很少需要写出它；如果要写，它是第三个模板参数，而 <code>hash_function()</code> 返回它的一份副本。
23|5. 什么时候 Swiss 表是正确的选择
24|当每个问题的答案都是“这个确切的键”时，就该用 Swiss 表：
25|成员判断：<em>这个 token 在表里吗？</em>
26|值查找：<em>这个名字对应哪条记录？</em>
27|流式输入时去重。
28|以字符串为键的缓存和索引。
29|而当问题涉及<em>范围</em>或<em>顺序</em>时，就留在 B 树这边：“所有以这个前缀开头的键”、“最小的那个”、“这个之后的下一个”。哈希表不扫遍全部就无法回答其中任何一个。
30|要点
31|<code>str_swiss_set</code> / <code>str_swiss_map</code> 是哈希表：只支持精确键操作，没有顺序。
32|遍历顺序是任意的，但可复现；绝不要依赖它。
33|<code>size()</code>、<code>capacity()</code> 和 <code>is_empty()</code> 都很便宜；<code>reserve(n)</code> 一次定好表大小，使批量插入不会反复重新哈希。
34|<code>insert_key</code> 返回 <code>{position, inserted}</code>；<code>inserted</code> 告诉你这个键原本是不是新的。
35|<code>erase_key</code>、<code>erase(it)</code>、<code>erase(first, last)</code> 的行为与 B 树家族一致。
36|写通过 <code>insert_key_or_assign</code> / <code>emplace_key</code> 或非 const 迭代器；读通过 <code>find_key</code>。
37|<code>find_key</code> 给出 <code>const_iterator</code>：只读。
