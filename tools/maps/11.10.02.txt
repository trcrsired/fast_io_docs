2|第11.10.2章: DNS（域名系统）
3|DNS 是互联网的电话簿。它把人类可读的域名（例如 <code>example.com</code>）翻译成计算机用来相互识别的 IP 地址（例如 <code>93.184.216.34</code>）。
4|DNS 如何工作
5|你的应用向操作系统请求解析 <code>example.com</code>
6|操作系统查询一个 DNS 解析器（通常是你的 ISP 提供的，或者像 <code>8.8.8.8</code> 这样的公共解析器）
7|解析器检查自己的缓存；若未命中，就依次查询根服务器、顶级域服务器，然后是权威服务器
8|解析器把 IP 地址返回给你的应用
9|你的应用连接到该 IP 地址
10|记录类型
11|<strong>A</strong> &mdash; IPv4 地址（例如 <code>93.184.216.34</code>）
12|<strong>AAAA</strong> &mdash; IPv6 地址（例如 <code>2606:2800:220:1:248:1893:25c8:1946</code>）
13|<strong>CNAME</strong> &mdash; 规范名（另一个域名的别名）
14|<strong>MX</strong> &mdash; 邮件交换（指定邮件服务器）
15|<strong>TXT</strong> &mdash; 文本记录（用于 SPF、DKIM 等）
16|<strong>NS</strong> &mdash; 名称服务器（把查询委派给其他 DNS 服务器）
17|<strong>SOA</strong> &mdash; 授权起始（关于该区域的管理信息）
18|<strong>PTR</strong> &mdash; 指针（反向 DNS：从 IP 到域名）
19|<strong>SRV</strong> &mdash; 服务定位（用于特定服务）
20|DNS over HTTPS（DoH）与 DNS over TLS（DoT）
21|传统的 DNS 查询以明文通过 UDP 53 端口发送，可能被拦截或篡改。现代的安全替代方案有：
22|<strong>DNS over HTTPS（DoH）</strong> &mdash; DNS 查询通过 HTTPS（443 端口）发送，加密并经过认证
23|<strong>DNS over TLS（DoT）</strong> &mdash; DNS 查询通过 TLS（853 端口）发送，加密并经过认证
24|<strong>DNSCrypt</strong> &mdash; 另一种加密 DNS 协议
25|这些协议可以防止窃听、中间人攻击和 DNS 欺骗，浏览器与操作系统的支持也越来越多。
