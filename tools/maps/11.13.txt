2|第11.13章: POSIX 文件 API
3|概述
4|在每个符合 POSIX 的系统上（Linux、FreeBSD、macOS 等），文件都是通过一小批系统调用来访问的：<code>open</code>、<code>openat</code>、<code>read</code>、<code>write</code>、<code>close</code> 等等。这些调用作用于一个原始的整数文件描述符（<code>int</code>）。
5|<code>fast_io</code> 把这些系统调用包装在两个类型背后：
6|<code>::fast_io::posix_file</code> &mdash; RAII 拥有式包装。它通过 <code>open</code>（或 <code>openat</code>）打开文件，并保证对象离开作用域时调用 <code>close</code>。
7|<code>::fast_io::posix_io_observer</code> &mdash; 对已有文件描述符的非拥有视图。它可平凡复制、没有析构函数，按值传递是安全的。
8|用 posix_file 打开文件
9|最常见的情形：按名字打开文件，然后用 <code>print</code> 和 <code>println</code> 读写。
10|<code>posix_file</code> 的构造函数会以由 <code>::fast_io::open_mode</code> 推导出的标志转发到 <code>open</code>。析构函数在文件描述符有效时调用 <code>close</code>。

18|原始的 POSIX I/O 系统调用
19|在使用 <code>fast_io</code> 的包装之前，先了解底层的 POSIX 系统调用会有帮助。它们是真正的内核入口（手册第 2 节）：
20|系统调用
21|用途
22|<code>open(path, flags, mode)</code>
23|按路径打开文件，返回一个 <code>int</code> 文件描述符。
24|<code>openat(dirfd, path, flags, mode)</code>
25|相对于某个目录文件描述符打开文件。比 <code>open</code> 更安全，因为它避免了路径解析带来的竞态。
26|<code>read(fd, buf, count)</code>
27|从 <code>fd</code> 最多读取 <code>count</code> 个字节到 <code>buf</code>。返回实际读取的字节数，出错时返回 -1。
28|<code>write(fd, buf, count)</code>
29|把 <code>buf</code> 中的 <code>count</code> 个字节写到 <code>fd</code>。返回实际写入的字节数，出错时返回 -1。
30|<code>close(fd)</code>
31|关闭文件描述符。<strong>永远需要</strong> &mdash; 文件描述符是有限资源。
32|<code>lseek(fd, offset, whence)</code>
33|改变文件偏移。<code>whence</code> 是 <code>SEEK_SET</code>、<code>SEEK_CUR</code> 或 <code>SEEK_END</code>。
34|<code>fdopen(fd, mode)</code>
35|把一个 C 的 <code>FILE*</code> 流关联到已有的文件描述符上，返回 <code>FILE*</code>。
36|这些系统调用<strong>不带缓冲</strong> &mdash; 每次调用都直接进入内核。这使得它们在操作很小或很频繁时很慢。<code>fast_io</code> 的带缓冲类型（如 <code>ibuf_file</code> 与 <code>obuf_file</code>）用用户态缓冲包装这些调用，性能好得多。
37|即使不用 fast_io 的 I/O，也可以用 posix_file 做 RAII
38|即使你更愿意直接调用原始 POSIX API（例如 <code>read</code> 与 <code>write</code>）而不使用 <code>fast_io</code> 的 <code>print</code> 与 <code>scan</code>，你<strong>仍然应该用 <code>::fast_io::posix_file</code> 来做 RAII</strong>。它的析构函数保证调用 <code>close</code>，所以你永远不会忘记关闭文件描述符。
39|当涉及异常或提前返回时，这一点尤其重要 &mdash; 没有 RAII，你必须在每一条退出路径上手动调用 <code>close</code>，这很容易出错。

42|小结
43|<code>::fast_io::posix_file</code> 是对 POSIX <code>open</code> / <code>close</code> 的 RAII 包装。
44|<code>::fast_io::posix_io_observer</code> 是对已有文件描述符的轻量、非拥有视图。
45|两个类型都能直接接入 <code>::fast_io::io::print</code>、<code>::fast_io::io::println</code> 与 <code>::fast_io::io::scan</code>。
46|你可以包裹任何原始的 <code>int fd</code>，而不用改动代码的其他部分。
47|原始 POSIX 系统调用有 <code>open</code>、<code>openat</code>、<code>read</code>、<code>write</code>、<code>close</code>、<code>lseek</code> 和 <code>fdopen</code>。它们不带缓冲，直接进入内核。
48|<strong>即使你直接调用原始 POSIX API</strong>（例如 <code>read</code> 与 <code>write</code>），<strong>也仍然要用 <code>::fast_io::posix_file</code> 做 RAII</strong>，以保证 <code>close</code> 被自动调用。这能防止资源泄漏，在有异常或提前返回时尤其如此。
49|关于 POSIX API 的更多细节，见 <a href="https://linux.die.net/man/" target="_blank" rel="noopener noreferrer">Linux man pages</a> 或你的系统文档。
