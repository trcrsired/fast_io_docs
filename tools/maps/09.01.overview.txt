3|概述
4|本节介绍 <code>fast_io_dsal</code> 中提供的所有序列容器。序列容器按顺序存放元素——第一个加入的元素位于位置 0，第二个位于位置 1，依此类推。我们会逐一介绍每种容器，解释数据局部性，并给出选择合适容器的经验法则。

54|2. 数据局部性与性能
55|容器在内存中存放元素的方式对性能有深远影响。现代 CPU 严重依赖<strong>缓存</strong>（L1、L2、L3）。当元素连续存放时，访问一个元素通常会把它的邻居一起带进缓存，后续访问几乎不花代价。

76|对大多数工作负载来说，<strong>连续存储胜出</strong>。CPU 缓存行通常是 64 字节。一个 <code>vector&lt;::std::size_t&gt;</code> 每缓存行能带来 16 个元素，而 <code>list&lt;::std::size_t&gt;</code> 每缓存行只带来 1 个元素（还要在指针上浪费内存）。因此，尽管链表提供 &Theta;(1) 插入，遍历的常数因子却可能差 10&ndash;50&times;。
77|3. 如何选择容器
78|以下是选择容器时的经验法则：
79|<strong>能不用容器就不用。</strong>如果可以用 I/O 操作完成任务（例如打印 &ldquo;Hello, World!&rdquo;），那就这么做。I/O 提供了一种无需动态分配就能处理无界数据的抽象。I/O 缓冲区往往比栈分配和堆分配都更高效。
80|<strong>除非有理由使用别的容器，就用 <code>::fast_io::vector</code>。</strong>它的缓存局部性最好，几乎在所有操作上都是最快的。
81|<strong>如果程序包含大量小元素，而空间开销很重要，就不要用 <code>list</code> 或 <code>forward_list</code>。</strong>链表中的每个结点至少要带一个指针（64 位系统上是 8 字节）的额外开销。
82|<strong>如果程序需要随机访问元素，就用 <code>vector</code> 或 <code>deque</code>。</strong>两者都提供 &Theta;(1) 的 <code>operator[]</code>，链表则没有。
83|<strong>如果程序需要在容器中间插入或删除元素，就用 <code>list</code> 或 <code>forward_list</code>。</strong>一旦迭代器定位好，插入与删除都是 &Theta;(1)。
84|<strong>如果程序需要在前端和后端插入或删除元素，但不需要在中间操作，就用 <code>deque</code>。</strong><code>vector</code> 只能在尾部高效增长。
85|<strong>如果程序只需要在读取输入时向中间插入元素，之后又需要随机访问：</strong> <ul> <li> 首先想一想，你是否真的需要中间插入。通常更简单的做法是先往 <code>vector</code> 里追加，之后再调用 <code>::std::ranges::sort</code>。 </li> <li> 如果确实必须往中间插入，可以考虑在输入阶段使用 <code>list</code>，输入完成后再把链表复制到 <code>vector</code> 中。 </li> </ul>
86|<strong>最佳实践：</strong>如果你不确定该用哪个容器，就把代码写成只使用 vector 和 list 共有的操作：使用迭代器（或 <code>_index</code> 系列操作），并且不要假定存在随机访问。这样在需要时就能轻松切换到 <code>vector</code> 或 <code>list</code>。
87|如果程序既需要随机访问<em>又</em>需要在中间插入或删除元素呢？答案取决于链表访问元素的相对代价与 vector 或 deque 中插入/删除的代价之间的对比。一般说来，应用的主要操作（是访问更多还是插入/删除更多）会决定选择。在这种情况下，通常需要针对两种容器都做性能测试。
88|要点
89|序列容器按插入顺序存放元素。
90|默认容器是 <code>::fast_io::vector</code>。
91|连续容器（<code>vector</code>、<code>array</code>、<code>string</code>）具有最好的缓存局部性。
92|链式容器（<code>list</code>、<code>forward_list</code>）缓存局部性差，但插入/删除是 &Theta;(1)。
93|<code>deque</code> 居于中间：分块存储，支持随机访问，两端都能快速增长。
94|当 I/O 操作就能完成任务时，完全不必使用容器。
95|从 <code>vector</code> 开始；只有当性能剖析显示瓶颈时才更换。
96|视图类型（<code>span</code>、<code>string_view</code>）不拥有内存。
