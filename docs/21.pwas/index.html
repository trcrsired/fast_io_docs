Ch21: Progressive Web Apps

中文（简体）

Why This Chapter Exists

Chapter 20 removed the operating system and asked what C++ has left. This chapter removes something else: the assumption that the program owns the machine. An app sandbox still has an operating system, a scheduler, a filesystem and a network stack, but the program is no longer allowed to reach them directly. The C++ standard has no name for that environment.

The result is not a smaller C++. It is C++ running in a place where fopen, fstream, stdout, getenv, main and legacy exceptions still exist but no longer mean what a desktop program assumes. That is the portability problem this chapter is about.

The answer this chapter argues for is the web platform: a Progressive Web App with a portable C++ core compiled to WebAssembly, a platform-independent UI, and no store gatekeeper between the developer and the user.

The Short Version

Cross-platform apps are usually built as a portable core plus a platform-specific UI. The core is C, C++ or assembly — codecs, DRM, crypto, networking, media pipelines, game engines. The UI is SwiftUI, Jetpack Compose, WinUI or ArkUI. The core is the asset; the UI is the replaceable part. The app sandbox attacks the portable layer by forcing the core into the platform language or behind platform-specific APIs.

A walled garden is a specific kind of operating system: one that forbids running binaries directly. Everything is an app, installed from a store, running in a sandbox with a permission list. Android, iOS, iPadOS, ChromeOS, Windows 11 S mode and the UWP platform are walled gardens. GNU/Linux, Windows, macOS, FreeBSD and SerenityOS are not.

The web is the one platform that is already on every device and needs no vendor's permission. A PWA is a website with a manifest and a service worker: installable, offline-capable, standalone, and distributable without a store. WebAssembly lets the same C++ core run there. That is the architecture this chapter builds: C++/WASM core, web UI, open distribution.

Key Takeaways

  • A PWA is a web app with offline support, installability and a service worker.
  • WebAssembly lets the same C++ core run inside the browser sandbox.
  • The sandbox changes which APIs are available; it does not remove the need for design.
  • Cache versioning and update strategy are part of correctness.
