Why This Chapter Exists

Every chapter before this one assumed an operating system underneath you: a heap behind malloc, a console behind print, an unwinder, a loader, a C library. This chapter removes all of it and asks what is left.

The answer is not "a smaller C++". It is C++ with the operating-system services taken away, and the interesting question is which of the things you were taught to rely on were actually the language and which were the operating system.

The chapter is deliberately short. Three pages: the problem, the library, and the talk.

The Three Pages

  1. 20.1 The Problem: C++ Was Not Designed for Freestanding — Linus Torvalds's 2004 message as the opening argument, the standard's definition of a freestanding implementation, why -ffreestanding is not a freestanding toolchain, the runtime bill for exceptions, RTTI, new, thread_local, startup, and floating point, and the headers that add no runtime dependency but were missing until C++23/26 (std::addressof, std::move, iterator traits, std::array, algorithms).
  2. 20.2 fast_io in a Freestanding Environment — the header split, containers whose allocator is part of the type, herbceptions, concept-constrained I/O where you define the device and print does the rest, and the checklist for a program with no hosted runtime.
  3. 20.3 Watch: Freestanding C++ — Past, Present, and Future — Ben Saks, CppCon 2019, and what to listen for.

The Short Version

C++ was designed as a hosted language, and the standard's model is still hosted-first: a freestanding implementation is a hosted one with a shorter header list, not a target with its own requirements. The features that need a heap, an unwinder, RTTI, a thread pointer, or start-up code therefore remained in the grammar and simply failed at link time on a bare target. The C++26 DIS ballot was disapproved on 23 October 2026 over contracts, so the freestanding additions it carried are still in an unapproved draft.

A freestanding C++ program therefore does four things: it bans legacy exceptions and RTTI, it supplies its own startup and heap, it never uses the global operator new, and it uses a library whose allocation source and I/O device are type parameters. That is what fast_io is for, and it is why the rest of this book uses it for everything.
