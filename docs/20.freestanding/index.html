Why This Chapter Is the Payoff

Every chapter so far assumed an operating system underneath you: a heap behind malloc, a console behind print, an unwinder, a loader, a C library. This chapter removes all of it and asks what is left. The answer is: everything this book taught you, minus the parts that were never anyone's idea of a good design.

The standard's own definition of the two kinds of implementation is short, and it is the reference for everything here: cppreference — freestanding. Read it once before continuing, because the rest of this chapter is about the gap between that page and what a compiler actually ships.

KindWhat it promisesWhere you meet it
Hosted __STDC_HOSTED__ is 1. A program has a main, may have several threads, and gets the whole standard library. Desktop, server, phone, a normal application build
Freestanding __STDC_HOSTED__ is 0. Whether a program has main at all is implementation-defined, threads are implementation-defined, and the standard library shrinks to a list of headers — a list that C++ left mostly empty for thirty years. Kernel, bootloader, firmware, an embedded board, a WebAssembly module

A freestanding implementation is not a smaller C++. It is C++ with the operating system taken away, and the interesting question is not "can the compiler still compile" — of course it can — but "which of the things you were taught to rely on were actually the operating system, and which were the language".

The One-Sentence Version

C++ was designed as a hosted language and spent thirty years insisting that freestanding was a corner case, while the code that runs on the most devices in the world — kernels, firmware, bootloaders, GPUs — could not use it without switching off the language's own features and half its library. That is the criticism Linus Torvalds made in 2004, it was correct, and this chapter is about what it takes to be on the right side of it today: no legacy exceptions, no RTTI, no hidden global heap, no hosted library — and an I/O library that does not assume any of them.
