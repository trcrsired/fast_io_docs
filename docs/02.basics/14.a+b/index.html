Basic Input and Output

A simple program that reads two integers and prints their sum. This demonstrates scan for input and println for output: 


#include <fast_io.h>
#include <cstddef>

int main()
{
    try
    {
        using namespace ::fast_io::iomnp;
        ::std::size_t a, b;
        scan(a, b);
        println(a + b);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
}

Even this tiny program cannot be trusted to succeed, and the code says so: the body is inside a try block, and the catch throws handler reports the failure and returns a non-zero exit code. In the next section you will see why.

I/O Always Can Fail

This is the first program in the tutorial that talks to the outside world, and that is the point where failure becomes possible. Every I/O operation can fail. There is no "safe" I/O call, and there is no configuration in which you can assume it worked.

Input fails all the time. It fails in the most ordinary ways:

  • the user typed x instead of a number, so scan(a, b) has nothing to parse — a parse error;
  • the input ended after one number, so the second scan reads end-of-file;
  • the number was too large for ::std::size_t, so it overflows;
  • the underlying device returned an error — a closed pipe, a reset connection, a bad sector on a disk, a network read that timed out.

Run the program above and feed it garbage: 


$ echo "x 4" | ./aplusb
[parse](3)Invalid format
$ echo $?
1

Output fails too. This surprises people, because in the iostream world nobody ever checks a print. But a write is a request to the operating system (or to a network peer), and requests are refused:

  • the disk filled up, so the buffered bytes could not be flushed ([posix](28)No space left on device);
  • the reader went away — the downstream process of a pipeline died, the terminal was closed ([posix](32)Broken pipe);
  • the output stream is a file handle that is not open for writing, or points at a full/read-only filesystem;
  • the output stream is a socket and the peer reset the connection ([posix](104)Connection reset by peer). We will meet sockets later; the important part is that even println("Hello World") can fail once the destination is not a local console but a network peer, a file on a full disk, or a process that has already exited.

So println is not a statement that "just prints". It is a fallible operation, and in fast_io every fallible operation says so in its type. Try it: 


#include <fast_io.h>

using namespace ::fast_io::io;

// println can fail: it may have to write to a device
static_assert(!noexcept(println("Hello World")));

// scan can fail: it may have to read and parse
static_assert(!noexcept(scan(::fast_io::c_stdin(), ::std::declval<int&>())));

A call that can fail is declared throws. If you call one, you must deal with the possibility of failure: either handle it with try { } catch throws (::std::error e) { }, or mark your own function throws so the failure travels to your caller. There is no third option — the compiler does not let you ignore it.

Why this tutorial does not use legacy C++ exceptions for this. Errors in fast_io are reported as herbceptions, and they are the only error mechanism used in this tutorial. Building them needs -fherbceptions -lherbceptions and one of our GCC or LLVM builds (MSVC does not support herbceptions). The complete rules — flags, the throw throws statement, the handler, and every error domain — are in Ch3.16: Herbceptions. From here on, every example that performs I/O uses the same try { } catch throws shape you see above.

What is a Manipulator?

In fast_io, a manipulator is a helper object that changes how input or output is interpreted or formatted. Instead of relying on unsafe format strings, manipulators make the intent explicit in the type system.

Manipulators are defined in the namespace fast_io::manipulators, which is aliased as fast_io::mnp for convenience. They make input and output safer, more explicit, and more portable than traditional stdio or iostream.

For example:

  • hex_get(a) — tells scan to read the variable a in hexadecimal.
  • hex(a) — prints a in lowercase hexadecimal.
  • hexupper(a) — prints a in uppercase hexadecimal.
  • base_get<N>(a) — reads a in base N (2 ≤ N ≤ 36).
  • base<N>(a) — prints a in base N.

Hexadecimal Manipulators

fast_io provides manipulators to read and print numbers in hexadecimal. hex_get reads input in hex, while hex and hexupper print output in lowercase or uppercase hex respectively: 


#include <fast_io.h>
#include <cstddef>

int main()
{
    try
    {
        using namespace ::fast_io::iomnp;
        ::std::size_t a, b;
        scan(hex_get(a), hex_get(b));
        println(hex(a + b), " ", hexupper(a + b));
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
}

Two hex numbers in, two hex numbers out. Bad input still ends in the handler, not in undefined behaviour.

Base-N Manipulators

Manipulators also support arbitrary bases from 2 to 36. Here’s an example using base 36: 


#include <fast_io.h>
#include <cstddef>

int main()
{
    try
    {
        using namespace ::fast_io::iomnp;
        ::std::size_t a, b;
        scan(base_get<36>(a), base_get<36>(b));
        println(base<36>(a + b));
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
}

About Manipulators

fast_io defines a rich set of manipulators to control input and output formatting. For convenience, the namespace fast_io::manipulators is aliased as fast_io::mnp.

  • base_get<N> — reads numbers in base N (where 2 ≤ N ≤ 36).
  • base<N> — prints numbers in base N.
  • hex — shorthand for base<16>.
  • hexupper — shorthand for base<16,true>, printing hex digits in uppercase.
  • left, right, internal, width, fill — field layout and padding.

These manipulators make it easy to work with different numeric bases without relying on unsafe format strings.

Key Takeaways

  • A + B is the smallest program that performs I/O, and I/O always can fail.
  • Input fails on malformed input, end-of-file, overflow, and device errors; output fails on full disks, broken pipes, closed handles, and reset connections. Even println("Hello World") can fail.
  • In fast_io every fallible operation is declared throws. A caller either handles it with try { } catch throws (::std::error e) { } or becomes throws itself.
  • Herbceptions are the only error-reporting mechanism in this tutorial; see Ch3.16 for the full rules.
  • Manipulators (hex, base<N>, hex_get, …) change formatting without format strings, and they do not change the fact that the surrounding I/O call can fail.
