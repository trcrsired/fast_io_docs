Ch19.2: C++ Legacy Exceptions

中文（简体）

1. What the Feature Is

The C++ exception mechanism is the one this book refers to as legacy exceptions. It has three keywords and one class hierarchy: 


#include <fast_io.h>
#include <stdexcept>

int main()
{
	try
	{
		int const a{84};
		for (int b : {2, 0})
		{
			if (b == 0)
			{
				throw ::std::runtime_error("division by zero");
			}
			::fast_io::io::print("84 / ", b, " = ", a / b, "\n");
		}
	}
	catch (::std::runtime_error const &e)
	{
		::fast_io::io::print("caught runtime_error: ", ::fast_io::mnp::os_c_str(e.what()), "\n");
	}
}


84 / 2 = 42
caught runtime_error: division by zero

The rules are: throw accepts a value of any type, copies it into implementation-owned storage, and abandons the current function; the unwinder walks the call stack frame by frame, destroying automatic objects as it goes, until it finds a matching handler. Matching is done with RTTI, so catch (::std::runtime_error const &e) matches a derived type and catch (...) matches anything. Handlers are tried in order, the first match wins, and a handler that rethrows with throw; continues the search.

Because ::std::exception and its what() were the only common base the language offered for thirty years, every library invented its own hierarchy below it, and the only way to get a message out of a caught error was a virtual call returning char const *. That is the design herbceptions replace, and it is worth knowing because you will read it in older code even though you will not write it.

2. What One Throw Costs

A legacy throw is not a jump. It allocates the exception object with __cxa_allocate_exception — a heap allocation, on the failure path, in every implementation — then calls __cxa_throw, which starts a two-phase walk of the stack that consults the personality routine for every frame, and matches handlers through the run-time type information. Then it destroys everything it walked past, and then it runs the handler.

Measure it. The program below throws the same error two hundred thousand times: half as a legacy ::std::runtime_error, half as a herbception. Both loops are fed from the same array so that nothing can be folded away, and both record how many errors reached the handler. 


#include <fast_io.h>
#include <stdexcept>

namespace
{
constexpr ::std::size_t round_count{200000};
constexpr ::std::size_t small_mask{3};

inline ::std::int_least64_t to_ns(::fast_io::posix_timespec64 d) noexcept
{
	return static_cast<::std::int_least64_t>(d.tv_sec) * 1000000000 + static_cast<::std::int_least64_t>(d.tv_nsec);
}

/* the values live in memory the optimizer cannot reason about */
::std::size_t count_legacy(::std::uint_least32_t const *values) throws
{
	::std::size_t caught{};
	for (::std::size_t i{}; i != round_count; ++i)
	{
		try
		{
			if (values[i] == 0)
			{
				throw ::std::runtime_error("riser");
			}
		}
		catch (::std::exception const &)
		{
			++caught;
		}
	}
	return caught;
}

::std::size_t count_herbception(::std::uint_least32_t const *values) throws
{
	::std::size_t caught{};
	for (::std::size_t i{}; i != round_count; ++i)
	{
		try
		{
			if (values[i] == 0)
			{
				throw throws ::std::errc::invalid_argument;
			}
		}
		catch throws (::std::error e)
		{
			++caught;
		}
	}
	return caught;
}
} // namespace

int main()
{
	auto *buffer{static_cast<::std::uint_least32_t *>(::std::malloc(round_count * sizeof(::std::uint_least32_t)))};
	if (buffer == nullptr)
	{
		::std::abort();
	}
	for (::std::size_t i{}; i != round_count; ++i)
	{
		buffer[i] = static_cast<::std::uint_least32_t>((i * 2654435761u) >> 7) & small_mask;
	}
	::std::size_t legacy_caught{};
	::std::size_t herbception_caught{};
	::std::int_least64_t legacy_ns{};
	::std::int_least64_t herbception_ns{};
	try
	{
		auto const start{::fast_io::posix_clock_gettime(::fast_io::posix_clock_id::monotonic_raw)};
		legacy_caught = count_legacy(buffer);
		legacy_ns = to_ns(::fast_io::posix_clock_gettime(::fast_io::posix_clock_id::monotonic_raw) - start);

		auto const start2{::fast_io::posix_clock_gettime(::fast_io::posix_clock_id::monotonic_raw)};
		herbception_caught = count_herbception(buffer);
		herbception_ns = to_ns(::fast_io::posix_clock_gettime(::fast_io::posix_clock_id::monotonic_raw) - start2);
	}
	catch throws (::std::error e)
	{
		::fast_io::io::print("error ", e, "\n");
		return 1;
	}
	::std::free(buffer);
	::fast_io::io::print("caught        ", legacy_caught, " ", herbception_caught, " throws out of ", round_count, "\n"
		"total ns      ", legacy_ns, " ", herbception_ns, "\n"
		"ps per throw  ", legacy_ns * 1000 / static_cast<::std::int_least64_t>(legacy_caught), " ",
		herbception_ns * 1000 / static_cast<::std::int_least64_t>(herbception_caught), "\n");
}


caught        49999 49999 throws out of 200000
total ns      46726099 44253
ps per throw  934540 885

Roughly one microsecond against one nanosecond. The interesting number is not the ratio; it is that the legacy failure path allocates and walks memory, which means it has a second way to fail (out of memory while reporting an error), a second way to be slow (cache misses on the frame tables), and no constant bound at all. The herbception path is two registers and a conditional jump, which is why the compiler can even delete it when nothing uses the result.

3. What It Requires From the Environment

Compile the same program to an object file and ask what it still needs: 


__cxa_allocate_exception
__cxa_begin_catch
__cxa_end_catch
__cxa_free_exception
__cxa_throw
__gxx_personality_v0
_Unwind_Resume

Four of those are the exception machinery itself: allocate, throw, begin/end catch, and the itanium personality routine __gxx_personality_v0, which is the function the unwinder calls to decide whether a frame catches anything (along with _Unwind_Resume from the platform unwinder). To make those calls work, a binary also needs:

  • an unwinder: a stack walker that understands the target's frame layout;
  • frame tables (.eh_frame) and a language exception table (.gcc_except_table) for every function on the path, registered with the loader so that the walker can find them;
  • a personality routine per ABI, and a runtime that owns the exception object's lifetime;
  • RTTI: the type information needed to match a handler.

That is a stack of platform-owned components, and each one can be missing:

Environment Why legacy exceptions are not available
Freestanding, kernels, bootloaders, embedded There is no unwinder, no loader to register tables with, and no __cxa_* runtime. The tables themselves are size you cannot pay, and the failure path would allocate
WebAssembly / WASI Unwinding is not part of the base target: the exception proposal and the JS-hosted variants all add engine surface, and toolchains ship -fno-exceptions by default
Any build with -fno-exceptions The compiler refuses the keywords outright. Many toolchains, game consoles, mobile SDKs and C++ standard library builds are configured this way
Across a GNU ↔ MSVC boundary Itanium and Microsoft exception ABIs are different: different tables, different personality routines, different object layout. An exception cannot cross, and the catch site does not exist for it
Inside a noexcept function An exception escaping it calls ::std::terminate — and everything a destructor or a move constructor may not do is enforced this way

So the honest statement is not "legacy exceptions are slow". It is: on most targets you will ship to, they do not exist at all, and where they do exist they are a heap allocation and a stack walk on the failure path. A library that reports failures with throw is a library that cannot be used in a kernel, in a Wasm module, on a board, or in any project that compiles with -fno-exceptions. That is most projects.

4. Therefore: You Cannot Use It

This book teaches legacy exceptions the way it teaches virtual and new (Ch18): to read them. You will maintain code that throws, you will call libraries whose failure path is a std::runtime_error, and you must know what happens when it runs. But your own code reports failures on the throws channel, and that is not a style preference — it is the only mechanism that works on every target this book targets.

Do not mix the two and hope. A single legacy throw forces the whole build to keep the unwinder, the tables and the personality routine, and it makes every caller's contract invisible. The last page of this chapter (Ch19.4) is the build list that removes the feature completely, so that nobody can reintroduce it by accident.

And when you must cross the boundary — your code calls a library that throws, or a library calls your code and wants an exception it understands — there is exactly one supported route, and it is Ch19.3.
