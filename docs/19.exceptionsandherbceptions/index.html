Ch19: Legacy Exceptions and Herbceptions

中文（简体）

What This Chapter Is For

You have been throwing and catching since Ch3.16, and every page since then has used the same two statements. What you have not seen is the table behind the error value: the thing that decides what a code means, what it prints, and which ::std::errc it corresponds to. This chapter is about that table, and about the other exception mechanism C++ has, which you must be able to read and must not use.

Mechanism What it costs What it costs in this book
Herbceptions Two words on the return path plus one failure bit — the same shape as returning an error code The only mechanism used, everywhere
Legacy C++ exceptions A heap allocation per throw, a two-phase stack walk, frame tables in every function, a personality routine, RTTI for handler matching Read-only. Removed from every build by flag (Ch19.4)

The short version of the second row: legacy exceptions are not merely slow (about a microsecond per throw, measured in Ch19.2). They are unavailable on most targets you will ship to — freestanding, kernels, bootloaders, embedded boards, WebAssembly — because the unwinder, the loader registration and the __cxa_* runtime they depend on do not exist there.

How to Read This Chapter

Read 19.1 only when you are writing a library that has a code space of its own. Read it carefully anyway, because it starts with the recommendation that saves the most work: the domains in the runtime are meant to be reused, and one of them covers nearly everything.

Read 19.2 and 19.3 as recognition training for the code you will inherit, and as the two directions of the bridge you will need on the day a dependency hands you a std::runtime_error. 19.4 is four lines to copy into your build right now.

  • Ch19.1: Defining and Overriding Error Domains — the five hooks of ::std::error_domain_singleton, the one that is mandatory, the error_domain<T> specialization, a complete CSV domain, and how to replace a shipped domain when the environment demands it
  • Ch19.2: C++ Legacy Exceptions — how the old mechanism works, what one throw costs measured, the runtime symbols it needs, and the environments where it simply does not exist
  • Ch19.3: Crossing the Boundary — legacy to herbceptions is automatic, herbceptions to legacy is throw_legacy_exception(), and what is lost on the way
  • Ch19.4: Ban Legacy Exceptions With Your Build Flags — -fno-exceptions -fno-rtti -fno-unwind-tables -fno-asynchronous-unwind-tables -fno-ident, and what each one deletes
