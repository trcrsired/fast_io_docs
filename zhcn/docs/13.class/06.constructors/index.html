第13.6章: 构造函数：对象如何诞生

English

1. 构造函数的职责

在第13.1章你可以写 point a{3, 4};，因为成员是公有的、类没有构造函数 — 花括号按顺序填充成员。这套语法是墙上的一个洞，一旦数据变为私有，它就消失了。必须有东西把调用者给的两个数字放到该放的地方，那个东西就是构造函数。

构造函数：

  • 与类同名，且没有返回类型；
  • 在创建对象时自动运行 — 你从不按名字调用它；
  • 把对象带入一个“每个成员函数都可以被调用”的状态 — 也就是不变量成立的状态（第13.5章）。 

class point
{
public:
	point(::std::int_least32_t x, ::std::int_least32_t y) noexcept : x_{x}, y_{y} {}
	//                                                              ^^^^^^^^
	//                                        the member initializer list

private:
	::std::int_least32_t x_{};
	::std::int_least32_t y_{};
};

point a{3, 4};   // still braces, but now they call the constructor
成员初始化列表是数据成员被初始化的唯一地方。构造函数体在每个成员都已经有值之后才运行。在函数体里赋值（x_ = x;）是第二次写，而对那些根本不能赋值的成员来说这不是一个选项。在列表里初始化，然后在函数体里做其余的事。

2. 成员按声明顺序初始化

列表是你写的，但编译器按成员的声明顺序读取它，而不是从左到右。如果两个顺序不一致，列表里的书写顺序就是一句读者会相信的谎言，而编译器会为此警告： 


class box
{
public:
	box(::std::int_least32_t w, ::std::int_least32_t h) noexcept : h_{h}, w_{w} {}
private:
	::std::int_least32_t w_{};   // w_ is initialized first...
	::std::int_least32_t h_{};   // ...then h_, whatever the list says
};


warning: 'box::h_' will be initialized after [-Wreorder]
warning:   'int_least32_t box::w_' [-Wreorder]
warning:   when initialized here [-Wreorder]

修正不花代价：按与声明相同的顺序写列表，这样两者永远不会不一致。只要有一个成员是用另一个成员初始化的，这一点就立刻变得重要 — 使用尚未初始化的成员是一个只在某些构建下才出现的 bug。

3. 一次讲全


#include <fast_io.h>
#include <cstdint>
#include <cstddef>
using namespace ::fast_io::io;

class point
{
public:
	point() noexcept : point{0, 0} // delegating constructor
	{
	}
	explicit point(::std::int_least32_t both) noexcept : point{both, both}
	{
	}
	point(::std::int_least32_t x, ::std::int_least32_t y) noexcept : x_{x}, y_{y}
	{
	}

	::std::int_least32_t x() const noexcept
	{
		return x_;
	}
	::std::int_least32_t y() const noexcept
	{
		return y_;
	}

private:
	::std::int_least32_t x_{};
	::std::int_least32_t y_{};
};

class label
{
public:
	// In-class initializers: what a member is worth when no constructor mentions it.
	::std::size_t length{};
	char first{'-'};
};

void draw(point const &p) throws
{
	println("point(", p.x(), ", ", p.y(), ")");
}

int main()
{
	try
	{
		point origin{};
		draw(origin);

		point square{3}; // explicit point(int_least32_t)
		draw(square);

		point p{7, 9};
		draw(p);

		label tag{};
		println("length = ", tag.length, ", first = ", ::fast_io::mnp::chvw(tag.first));
	}
	catch throws (::std::error e)
	{
		print("failed: ", e, "\n");
	}
}


point(0, 0)
point(3, 3)
point(7, 9)
length = 0, first = -

那个程序里的四个想法：

  • 类内初始化器（::std::size_t length{};）。带初始化器声明的成员，在任何构造函数没有提到它时就取那个值。这就是为什么 label tag{}; 在完全没有写构造函数的情况下得到 length = 0, first = -。优先用它们：默认值紧挨着成员，而不必在每个构造函数里重复。
  • 委托构造函数（point() noexcept : point{0, 0} {}）。一个构造函数可以把工作交给同类的另一个构造函数。于是默认构造函数里一个数据都没有：“原点是零、零处的点”这句话只写一次，写在那个知道如何构造点的构造函数里。
  • 重载的构造函数与其他任何重载一样，按实参挑选。point{}、point{3} 和 point{7, 9} 分别到达三个不同的构造函数。
  • 一旦你写了任何构造函数，编译器就不再为你生成默认构造函数。只有 point(x, y) 的 class point 不能被默认构造，编译器会直白地说： 
    
error: no matching function for call to 'point::point()'
    如果两个都要，就两个都声明。point() noexcept = default; 请求编译器生成默认构造函数，它会使用成员的类内初始化器。

4. explicit：拒绝悄悄发生的转换

只接受一个实参的构造函数同时也是从该实参到类类型的转换。正是它让下面这段能编译： 


void draw(point const &p) throws;

draw(5);   // silently means: point{5}

当单个数字确实是点的完整描述时（一个正方形），这很舒服。但大多数时候它是一个陷阱：读 draw(5) 的人不知道背后构造了一个点，而且这种转换还会在重载决议中发生。在构造函数上加 explicit 恰好禁止这一个转换，别的都不影响： 


explicit point(::std::int_least32_t both) noexcept : point{both, both} {}


error: invalid initialization of reference of type 'const point&' from expression
       of type 'int'
note:   in passing argument 1 of 'void draw(const point&)'

point{3} 与 point square{3}; 仍然可用 — 那里通过花括号的转换是刻意的。失效的是那个看不见的转换。除非你真的希望这个类表现得像那个实参，否则给每个单实参构造函数加上 explicit；这是本教程的默认做法。

可能失败的构造函数是 throws。校验实参很正常（第13.5章的 account 拒绝负的开户余额）。带校验的构造函数声明为 throws，抛出 ::std::errc::invalid_argument，而一个存在的对象因此被保证是有效的 — 在程序的余下部分，无需再检查。
