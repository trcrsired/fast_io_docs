第13.3章: const 成员函数：承诺不修改

English

1. 参数列表后面的 const 意味着什么

每个成员函数都把它被调用的那个对象作为一个看不见的指针 this 接收（第13.7章）。在参数列表后面写 const 会改变那个指针的类型： 


::std::int_least32_t value()   const noexcept;   // inside: this is counter const *
void                  add(::std::int_least32_t n) noexcept;   // inside: this is counter *

它所做的就这些，而这就足够同时给你两个保证：

  • 在函数内部，你不能给数据成员赋值，也不能调用不是 const 的成员函数。编译器强制这个承诺；它不是注释。
  • 在函数外部，一个 const 对象 — 或者任何通过 const & 到达的对象 — 只能调用 const 成员函数。所以接受 counter const & 的函数，在物理上无法修改那个计数器。

2. 规则：只读的成员函数就是 const

对你写的每个成员函数问一个问题：它会改变对象吗？如果答案是不会，声明就以 const 结尾。这就是规则，没有值得例外的情形。 


#include <fast_io.h>
#include <cstdint>
using namespace ::fast_io::io;

class counter
{
public:
	void add(::std::int_least32_t n) noexcept
	{
		value_ += n;
	}
	::std::int_least32_t value() const noexcept
	{
		return value_;
	}

private:
	::std::int_least32_t value_{};
};

// A const reference can only call const member functions.
void show(counter const &c) throws
{
	println("value = ", c.value());
}

int main()
{
	try
	{
		counter c{};
		c.add(5);
		show(c);

		// A const reference to the same object: a read-only view of it.
		counter const &frozen{c};
		show(frozen);
		println("frozen.value() = ", frozen.value());
	}
	catch throws (::std::error e)
	{
		print("failed: ", e, "\n");
	}
}


value = 5
value = 5
frozen.value() = 5

show 接受 counter const &，因为它只读。它调用 c.value()，而这能编译仅仅因为 value() 是 const。如果 value() 在写的时候没加 const，这个再普通不过的函数就无法编译，而需要修改的地方是 value()，不是 show。

当你试图修改一个 const 对象 — frozen.add(1) — 编译器会说： 


error: passing 'const counter' as 'this' argument discards qualifiers [-fpermissive]
note:   in call to 'void counter::add(int_least32_t)'

“discards qualifiers”（丢弃限定符）的意思是这次调用会丢掉 const，而编译器不会让你不小心这么做。

不要靠撒 const_cast 来消音。如果你需要在 const 成员函数里写入，那么要么这个函数并非真的只读（去掉它的 const，并接受它不能在 const 对象上调用），要么交给你的那个对象本来就不该是 const。两者都是关于你设计的信息；强制转换把信息丢掉，留下的程序在说谎。

3. 为什么这是本章最有价值的习惯

const 会以最好的方式传染。一旦只读的成员函数被标记出来，const & 参数就会到处都是，程序里的每个函数都在记录 — 并由编译器检查 — 谁可以改什么。三个具体后果：

  • const & 参数是一个你可以信任的承诺。当你调用 show(c) 时，你知道计数器会以进来的样子返回。你不必去读 show 的实现，只读它的签名就够了。
  • 错误在发生处被捕获。漏写 const 会在调用点就产生编译错误，而不是在三个函数之后得到一个错误的数字。
  • 接口保持诚实。没有 const 的成员函数在宣告“我可能会修改这个对象”。于是类的读者可以去看那份短的修改列表，从而知道状态在哪些地方变化。
两个成员函数，同名，只有 const 不同，是两个不同的重载。这偶尔有用 — 一个可变访问器和一个只读版本：

::std::int_least32_t &value() noexcept       { return value_; }
::std::int_least32_t  value() const noexcept { return value_; }
编译器根据对象挑选：可变的 counter 得到前一个，const 的得到后一个。要有意识地使用这一点，不要误用：交出一个私有数据成员的可变引用，等于把你在第13.5章获得的控制权又让了出去。

4. const 成员函数与 throws

这两个规格是独立的，都出现在声明的末尾，const 在前： 


::std::int_least32_t value() const noexcept;   // read, cannot fail
void report() const throws;                    // read, may fail (it prints)

在上面的例子里，show 是 throws 而不是 noexcept，因为它要打印，而它在 main 里的调用者把调用包进了 try { } catch throws (::std::error e)。类本身不需要为这一点的成立做任何事：成员函数的失败会从 c.value() 传出，再从 show 传出，最后在程序准备好处理它的地方被捕获（第3.16章）。
