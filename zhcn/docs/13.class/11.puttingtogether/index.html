English

1. 完成后的类

这就是贯穿全章生长起来的那个 account。现在它用上了本章的每一个想法：私有的不变量、藏在具名构造函数背后的私有构造函数、带检查的修改器、const 访问器、通过 *this 实现的链式调用、类范围的静态数据与静态函数，以及一个 friend。 


#include <fast_io.h>
#include <cstdint>
#include <cstddef>
using namespace ::fast_io::io;

class account
{
public:
	// ---- creation: a named constructor, the only door into the class ----
	static account open(::std::int_least64_t opening) throws
	{
		if (opening < 0)
		{
			throw throws ::std::errc::invalid_argument;
		}
		return account{opening};
	}

	// ---- the interface: what anybody may do with an account ----
	::std::int_least64_t balance() const noexcept
	{
		return balance_;
	}
	::std::size_t id() const noexcept
	{
		return id_;
	}

	account &deposit(::std::int_least64_t amount) throws
	{
		if (amount <= 0)
		{
			throw throws ::std::errc::invalid_argument;
		}
		balance_ += amount;
		return *this;
	}
	account &withdraw(::std::int_least64_t amount) throws
	{
		if (amount <= 0 || amount > balance_)
		{
			throw throws ::std::errc::invalid_argument;
		}
		balance_ -= amount;
		return *this;
	}

	// ---- facts about the class itself ----
	static ::std::size_t opened() noexcept
	{
		return next_id_ - 1;
	}
	static constexpr ::std::size_t iban_length{34};

	// ---- an outside function we let in ----
	friend bool richer(account const &a, account const &b) noexcept
	{
		return a.balance_ > b.balance_;
	}

private:
	// Only open() may call this; nobody else can even name it.
	explicit account(::std::int_least64_t opening) noexcept
		: balance_{opening}, id_{next_id_++}
	{
	}

	::std::int_least64_t balance_{};
	::std::size_t id_{};
	inline static ::std::size_t next_id_{1};
};

int main()
{
	try
	{
		auto a{account::open(100)};
		auto b{account::open(250)};

		a.deposit(50).deposit(25);
		b.withdraw(100);

		println("a: id = ", a.id(), ", balance = ", a.balance());
		println("b: id = ", b.id(), ", balance = ", b.balance());
		println("richer(a, b) = ", richer(a, b));
		println("accounts opened = ", account::opened(), ", iban length = ", account::iban_length);

		a.withdraw(1000); // breaks the invariant, so it is refused
	}
	catch throws (::std::error e)
	{
		print("refused: ", e, "\n");
	}
	println("the program keeps running");
}

b: id = 2, balance = 150
richer(a, b) = 1

2. 回头解读

类中的部分 它在做什么 出自
static account open(...) throws 唯一的入口：一个在对象存在之前完成校验的具名构造函数，也是私有构造函数的唯一调用者。 第13.9章
private: 之后的 explicit account(...) noexcept 用 open 已经检查过的值构造对象。它被藏起来，以便没有人能跳过检查。 第13.4章、第13.6章
balance() const noexcept 返回值形式的只读访问器，可在 const 对象上调用。 第13.3章
deposit(...) throws、withdraw(...) throws 余额唯一可能改变的两条途径，各自在写入前检查不变量，各自用 ::std::errc::invalid_argument 报告拒绝。 第13.5章
返回类型为 account & 的 return *this; 链式调用：a.deposit(50).deposit(25); 第13.7章
inline static ::std::size_t next_id_{1}; 所有账户共享的标识符来源，只有构造函数会碰它。 第13.8章
static ::std::size_t opened() noexcept 关于类的一个事实，不需要任何对象就能调用。 第13.9章
friend bool richer(account const &, account const &) 类自己选择允许的对称比较，从而让余额保持私有。 第13.10章

注意类里没有什么：没有公有数据成员，没有余额的 setter，没有交出引用的 getter，也没有任何不经过检查就造出账户的办法。main 中类外面的每一行，都可以由从未见过该定义的人写出来，而他们依然造不出一个无效的账户。

3. 设计清单

当你写自己的类时，把这个清单走一遍：

  1. 把不变量写成一句话。如果写不出来，这个类型大概是两个类型，或者它就是一个普通 struct，不需要墙。
  2. 把数据设为私有，其他东西也一律私有，直到证明需要公开。接口就是你要保留的那一小份名字。
  3. 让每个构造函数都建立不变量，并让带校验的构造函数是 throws。先校验，再写入。
  4. 给每个只读成员函数加 const，返回值为值（或 const &），绝不要返回对存储的可写引用。
  5. 当构造函数本来会变成一个谜题时，为每种构造方式给类起个名字：open、from_history、parse。
  6. 把每个成员函数标为 noexcept 或 throws。如果成员函数可能失败，调用者就必须处理它；这是签名必须携带的信息。
  7. 关于类的事实就用静态成员，并且把任何可变静态成员当作需要理由的共享状态。
  8. 只用 friend 为对象之间对称的操作开墙，并且要在确认成员函数或访问器做不到之后才这么做。

4. 代价最大的错误

错误 代价 应该这样做
私有数据，外加一个 getter 和 一个什么都接受的 setter。 墙只是装饰：不变量依然没有被强制，而类变长了。 给操作起名字（deposit、withdraw），并在它们内部检查。
访问器上忘记 const。 没有人能把你的类型传给接受 T const & 的函数，于是每个调用者都变成非 const，安全性随之蒸发。 在你写下不会写入的成员函数的那一刻就加上 const。
从访问器返回 ::std::int_least64_t &。 a.balance() = -1000; 能编译，而不变量荡然无存。 按值返回，对大成员则返回 const &。
在构造函数体里赋值，而不是用初始化列表。 成员被写两次，列表顺序不再匹配，而不能赋值的成员干脆无法工作。 在成员初始化列表里按声明顺序初始化。
单实参构造函数没有 explicit。 悄悄发生的转换把一次错误的调用变成错误的对象。 加 explicit，除非这种转换正是该类型的意义所在。
一边是带检查的工厂函数，一边是不检查的公有构造函数。 程序里一半对象有效、一半无效，不变量一文不值。 只留一扇门。把不检查的构造函数设为私有。
捕获赫布异常后，当作操作已经发生一样继续。 调用者以为存款成功了。悄悄给出的错误答案比停下来更糟。 处理它、向上传播它，或者让它到达顶层并让程序停下。

5. 你现在的位置

你已经能定义一个拥有自己数据的类型，决定外部可以做什么，维持一个承诺，并用本教程处处使用的唯一方式报告失败：throws 加 catch throws (::std::error e)。这足以支撑语言剩余的部分。后面的一切 — 运算符、泛型代码、标准库自己的类型 — 都是用这样的类写成的。

要带走的一件事。类是一个承诺。private 让承诺可信，const 让承诺可读，构造函数让承诺从对象存在的第一刻起就为真，而 throws 是当有人要求承诺无法允许的东西时发生的事。
