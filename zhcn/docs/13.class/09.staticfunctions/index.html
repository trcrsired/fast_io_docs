第13.9章: 静态成员函数

English

1. 没有对象的成员函数

静态成员函数是不在对象上调用的成员函数。它没有 this（第13.7章），用类名而不是变量名调用，而且即使该类的对象一个都不存在时也能调用： 


::std::size_t n{account::opened()};   // no object involved

其他一切不变：它在类内部，所以遵守同样的访问规则 — 它可以读写私有成员，包括私有构造函数。“在对象之外、在墙之内”这种组合，正是它有用的原因。

2. 静态成员函数不能是 const

成员函数上的 const 是关于 this 的陈述，而静态成员函数没有 this，所以两者不能结合： 


error: static member function 'static int_least32_t counter::instances()'
       cannot have cv-qualifier

出于同样的理由，它也不能指名非静态数据成员：没有对象，所以“这个对象的成员”没有意义。静态成员当然可以使用 — 它们属于类，而静态成员函数依附的正是类。

3. 主要用途：具名构造函数

构造函数只有一个名字：类的名字。如果一个类可以用几种方式、几种不同含义来构造，构造函数就不再富有表达力：account{100} 与 account{100, 5} 并没有说明那些数字是什么。静态成员函数给构造过程一个名字，并让你在对象存在之前先做工作： 


#include <fast_io.h>
#include <cstdint>
#include <cstddef>
using namespace ::fast_io::io;

class account
{
public:
	// A named constructor: the only way to make an account.
	static account open(::std::int_least64_t opening) throws
	{
		if (opening < 0)
		{
			throw throws ::std::errc::invalid_argument;
		}
		return account{opening};
	}

	// No object needed: it reports on the class as a whole.
	static ::std::size_t opened() noexcept
	{
		return next_id_ - 1;
	}

	::std::int_least64_t balance() const noexcept
	{
		return balance_;
	}
	::std::size_t id() const noexcept
	{
		return id_;
	}

private:
	explicit account(::std::int_least64_t opening) noexcept
		: balance_{opening}, id_{next_id_++}
	{
	}

	::std::int_least64_t balance_{};
	::std::size_t id_{};
	inline static ::std::size_t next_id_{1};
};

int main()
{
	try
	{
		auto a{account::open(100)};
		auto b{account::open(250)};

		println("a: id = ", a.id(), ", balance = ", a.balance());
		println("b: id = ", b.id(), ", balance = ", b.balance());
		println("accounts opened: ", account::opened());

		auto bad{account::open(-5)};
		println("never reached: ", bad.balance());
	}
	catch throws (::std::error e)
	{
		print("account::open failed: ", e, "\n");
	}
}


a: id = 1, balance = 100
b: id = 2, balance = 250
accounts opened: 2
account::open failed: [posix](22)Invalid argument
  • 构造函数是私有的。account 真正的构造函数是 private，所以类外部写 account{100} 无法编译。open 是唯一的门，而且是一扇会检查的门。
  • 名字说明了正在发生什么。account::open(100) 读起来像对类的一个动作，而不是在猜两个数字分别放到哪里。
  • 检查在对象存在之前发生，而且只发生一次。失败的 open(-5) 在账户被构造之前就抛出，所以不存在“半成品对象存在”的瞬间，也不需要任何“这个对象有效吗”的标志。这与带校验的构造函数是同一个保证（第13.5章），只是名字更好。
  • 多个具名构造函数可以并存，不需要重载技巧：open(...)、open_with_overdraft(...)、from_history(...)。每个名字都告诉读者它回答的是哪个问题。

4. 什么时候该写一个

用静态成员函数 用普通成员函数
操作是关于类整体的：存在多少个、上限是什么、如何从另一种表示构造一个。 操作是关于某个对象的：deposit、withdraw、balance。
你需要在构造对象之前校验或变换实参。 对象已经存在，你要修改或读取它。
你必须访问私有成员，却没有对象可供访问。 你有对象 — 那是通常情形。
静态成员函数就是一个有访问权限的自由函数。如果一个辅助函数不需要私有成员，概念上也不属于这个类，那就把它写成类外面的自由函数。这样能让类保持小，也让辅助函数可以独立测试。反过来，如果辅助函数需要碰私有数据，friend（第13.10章）是另一种在不公开数据的前提下允许它访问的办法。
静态成员函数是类接口的一部分。一旦它出现在 public: 之后，它就是你承诺要保留的名字，与公有成员函数完全一样。只有类外面的调用者真的需要它时才放在那里；只被 open 使用的校验辅助函数应当放在 private: 之后。
