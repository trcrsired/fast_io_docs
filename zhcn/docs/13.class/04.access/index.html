第13.4章: 访问控制：public 与 private

English

1. 两扇门

一个类有两个访问级别，写作标签，标签一直生效到下一个标签为止：

  • public — 任何人都可以使用这些名字。这是接口：你承诺要保留的那部分。
  • private — 只有本类的成员函数和友元可以使用这些名字。这是实现：你下周可以重写的那部分。 

class point
{
public:
	void set(::std::int_least32_t x, ::std::int_least32_t y) noexcept;  // the interface
	::std::int_least32_t sum() const noexcept;
private:
	::std::int_least32_t x_{};   // the implementation
	::std::int_least32_t y_{};
};

编译器拒绝外部访问私有名字，并指出是哪个成员、声明在哪里： 


error: 'int_least32_t point::x_' is private within this context
note:   declared private here

同一个程序，把私有成员在类内部使用，那里才是允许访问的地方： 


#include <fast_io.h>
#include <cstdint>
using namespace ::fast_io::io;

class point
{
public:
	// This is the whole interface: two things you may do to a point.
	void set(::std::int_least32_t x, ::std::int_least32_t y) noexcept
	{
		x_ = x;
		y_ = y;
	}
	::std::int_least32_t sum() const noexcept
	{
		return x_ + y_;
	}

	// Inside the class, every object of the class is visible in full.
	::std::int_least32_t dx_to(point const &other) const noexcept
	{
		return other.x_ - x_;
	}

private:
	// Nobody outside the class can touch these two.
	::std::int_least32_t x_{};
	::std::int_least32_t y_{};
};

int main()
{
	point a{};
	a.set(3, 4);
	println("a.sum()     = ", a.sum());

	point b{};
	b.set(10, 4);
	println("a.dx_to(b)  = ", a.dx_to(b));
}


a.sum()     = 7
a.dx_to(b)  = 7

2. 访问权授予的是类，而不是对象

这正是人们常搞错的细节。private 并不意味着“只有我可以看自己的数据”，而是“只有写在这个类内部的代码可以看这份数据” — 任何本类的对象，无论它属于谁： 


::std::int_least32_t dx_to(point const &other) const noexcept
{
	return other.x_ - x_;   // other is somebody else's point, and it is still fine
}

dx_to 是 point 的成员函数，所以它站在墙内，可以像读自己的 x_ 一样轻松读 other.x_。这就是为什么类可以在不暴露任何东西的前提下实现两个对象之间的比较、算术和校验：墙围的是定义，不是某个特定对象（第13.10章展示了同一个想法的外部函数版本）。

3. struct 与 class 是同一回事

它们之间只有一个差别：默认访问级别。在 struct 里，最前面的成员是 public；在 class 里，它们是 private。 


struct a
{
	::std::int_least32_t x;   // public
};

class b
{
	::std::int_least32_t x;   // private
};


error: 'int_least32_t b::x' is private within this context
note:   declared private here

本教程遵循的约定，也是你读任何库时都会见到的约定：

写 何时
struct 这个类型就是一堆裸值，没有不变量、没有行为：坐标、一个范围、一个键/值对。使用者会直接读写成员，没有什么需要保护。
class 这个类型有不变量、有接口、有行为。一切都私有着，直到你决定某样东西应该是公有的。
你到目前为止在本章看到的一切都是 struct 风格的类。从这里开始，示例改用 class 与私有数据，因为那才是有意思的情形。关键字只是默认值，不是另一门语言：一个在顶部显式写了 public: 的 class，与等价的 struct 是同一个类型。

4. 接口小是优点

访问控制是你决定承诺大小的地方。学习时的本能是把一切都设成 public“这样才灵活”。这个本能是反的：每个公有名字都是你若不破坏别人的代码就无法更改的东西，而每个公有数据成员都是你决定不去维持的不变量。

对你即将放到 public: 后面的每个名字问三个问题：

  1. 调用者真的需要它吗？如果调用者用一个成员函数就能完成工作，那数据成员就保持私有。
  2. 调用者能误用它吗？公有的 ::std::int_least64_t balance 让任何人都能往里写 -1000。私有的加上带检查的 withdraw() 就无法被误用（第13.5章）。
  3. 改掉它会不会破坏不属于我的代码？如果会，那它就是一个承诺。承诺应当少、小、真。
访问控制是编译期规则，不是安全机制。它防的是意外，以及写正常代码的人误用。它挡不住一个手里有指针和 reinterpret_cast 的执着程序员，它也不是在内存里保守秘密的手段。它的价值在于：诚实的程序不可能误伤一个类，而编译器会在确切的那一行告诉你。
关上门之后的账单立刻就到了。point a{3, 4}; 在第13.1章能用，是因为成员是公有的、类没有构造函数。成员私有之后，外部就无法写入这两个值了。这不是缺陷，而是设计中缺失的另一半：取代它的是构造函数，见第13.6章。在此之前，示例先创建一个对象再通过成员函数填充它（a.set(3, 4)）。
