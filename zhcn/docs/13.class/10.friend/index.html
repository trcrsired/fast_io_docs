第13.10章: 友元：放进一个外来者

English

1. 属于类型、却无法作为成员的操作

有时你需要的操作接受该类的两个对象并把它们平等对待。两个点的中点、两个点之间的距离、两个向量的和：它们都不是“左手那个对象的方法”，而写在类外面也做不到，因为它需要的数据是私有的。

友元（friend）就是类给予某个具名外来者以自身成员函数所拥有的访问权限的方式。许可在类内部授予，由拥有数据的那个类来授予： 


class point
{
public:
	friend point midpoint(point const &a, point const &b) noexcept;   // granted here
private:
	::std::int_least32_t x_{};
	::std::int_least32_t y_{};
};

friend 那一行是一个普通自由函数的声明，只不过它被允许往里看。它不是成员：它没有 this，不在对象上调用，也不属于类的成员函数列表。

2. 友元函数与友元类


#include <fast_io.h>
#include <cstdint>
using namespace ::fast_io::io;

class point
{
public:
	point(::std::int_least32_t x, ::std::int_least32_t y) noexcept : x_{x}, y_{y}
	{
	}

	::std::int_least32_t sum() const noexcept
	{
		return x_ + y_;
	}

	// One named function may look inside.
	friend point midpoint(point const &a, point const &b) noexcept;

	// A whole class may look inside.
	friend class inspector;

private:
	::std::int_least32_t x_{};
	::std::int_least32_t y_{};
};

point midpoint(point const &a, point const &b) noexcept
{
	return point{(a.x_ + b.x_) / 2, (a.y_ + b.y_) / 2};
}

class inspector
{
public:
	static void dump(char const *label, point const &p) throws
	{
		println(::fast_io::mnp::os_c_str(label), ": x = ", p.x_, ", y = ", p.y_);
	}
};

int main()
{
	try
	{
		point a{0, 0};
		point b{10, 20};

		auto m{midpoint(a, b)};
		println("midpoint.sum() = ", m.sum());

		inspector::dump("midpoint", m);
	}
	catch throws (::std::error e)
	{
		print("failed: ", e, "\n");
	}
}


midpoint.sum() = 15
midpoint: x = 5, y = 10

两种授予，两种形状：

  • friend point midpoint(point const &, point const &) — 一个自由函数可以读 x_ 与 y_，也可以使用公有构造函数。别的什么都不变。
  • friend class inspector; — inspector 的每个成员函数都可以读它们，包括上面用到的静态 dump。授予的对象是整个类，正如 private 也是授予整个类一样（第13.4章）。
为什么 midpoint(a, b) 能被调用。一个只在类内声明为 friend 的函数对普通名字查找不可见，但当它的某个实参具有该类类型时它会被找到 — 这就是实参依赖查找，也正是 midpoint(a, b) 不需要在命名空间作用域再声明一次就能解析的原因。如果你希望实参里完全不含该类类型时也能调用它，那就同时在命名空间作用域声明它。

3. 友元不是什么

人们以为 实际发生的是
“友谊是双向的。” 并非如此。如果 inspector 是 point 的友元，那么 inspector 可以看 point 内部 — 但 point 什么也没得到，inspector 自己的私有成员对 point 依然是私有的。
“我朋友的也是我的朋友。” 它不可传递。inspector 是 point 的友元，这并不说明任何别的类。
“我可以把自己声明为友元。” 不行。只有拥有数据的类才能授予访问权。友谊是给予的，从不被索取。
“友元就是成员。” 不是。友元函数内部没有 this，它也不列在类的成员函数中。

4. 最后才用它

friend 是你能在墙上开的最窄的洞，但它仍然是一个洞。授予之前，按这个顺序检查更便宜的做法：

  1. 能用成员函数做吗？如果这个操作有一个自然的主体对象，就把它做成成员。midpoint 没有自然主体 — 这就是它不作为成员的原因。
  2. 能用公有接口做吗？基于公有访问器（a.x()、a.y()）的友元函数完全不需要授权。当访问器已经存在时就那样做；这能让类保持封闭，也让函数可测试。
  3. 它是关于类而不是关于对象的吗？那就该用静态成员函数（第13.9章）。
  4. 否则 — 两个对象之间的对称操作是经典情形 — friend 就是合适的工具。
friend 会制造耦合。友元函数现在成了类实现的一部分：改动数据成员，友元就坏了，尽管它在类里并不显眼。对真正属于该类型接口的两三个操作来说，这是可以接受的；而如果你把友谊发给任何需要走捷径的东西，它就是一个维护陷阱。如果好几个外来者都需要同一份数据，设计问题通常是那份数据该不该有公有访问器 — 而不是要不要加第五个友元。
运算符也是这样写的。像 + 或 == 这样接受两个该类对象的运算符，与 midpoint 形状相同，通常也因为同样的理由声明为 friend。运算符会在教程后面、在你手上有了类和引用之后再讲。
