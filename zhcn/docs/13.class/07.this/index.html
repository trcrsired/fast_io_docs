第13.7章: this 指针

English

1. 每个成员函数都悄悄接收了对象

当你写 c.add(2) 时，编译器必须告诉 add 该往哪个计数器上加。它通过把对象作为一个额外实参传进去 — 第一个实参，在参数列表里看不见，在函数内部通过关键字 this 到达： 


c.add(2);        // what you write

// what the member function actually receives:
//    (counter *this, ::std::int_least32_t n)

this 是指向那个对象的指针。所以 this->value_、(*this).value_ 和裸的 value_ 是同一个成员的三种写法。你很少需要写它；需要写的三种情形见下文。

2. 情形 1：参数遮住了成员

如果一个参数与某个数据成员同名，参数胜出，成员从视野中消失。this-> 把它带回来： 


counter &set(::std::int_least32_t value) noexcept
{
	this->value_ = value;   // member on the left, parameter on the right
	return *this;
}

很多人干脆避免这个问题，把参数换个名字（n，或者 new_value）— 那也行，而且名字更短。两种做法都可以，当两个名字冲突时，this-> 是显式表达的方式。

3. 情形 2：返回你被调用的那个对象

*this 是对象本身，不是指向它的指针。返回对它的引用，就能让调用者在同一个对象上链式调用，因为链中的每次调用都是在前一次调用返回的那个对象上的成员函数： 


#include <fast_io.h>
#include <cstdint>
using namespace ::fast_io::io;

class counter
{
public:
	explicit counter(::std::int_least32_t value) noexcept : value_{value}
	{
	}

	// `value` hides the member, so the member needs this-> .
	counter &set(::std::int_least32_t value) noexcept
	{
		this->value_ = value;
		return *this;
	}

	counter &add(::std::int_least32_t n) noexcept
	{
		value_ += n;
		return *this; // the object we were called on
	}

	::std::int_least32_t value() const noexcept
	{
		return value_;
	}

	bool same_as(counter const &other) const noexcept
	{
		return this == &other;
	}

private:
	::std::int_least32_t value_{};
};

int main()
{
	counter c{0};
	c.add(1).add(2).add(3); // chaining: each call returns *this
	println("after chaining: ", c.value());

	c.set(10);
	println("after set(10):  ", c.value());

	counter d{10};
	println("c.same_as(d) = ", c.same_as(d));
	println("c.same_as(c) = ", c.same_as(c));
}


after chaining: 6
after set(10):  10
c.same_as(d) = 0
c.same_as(c) = 1

返回类型是 counter & — 对对象本身的引用，不是指针也不是另作一份的值，所以 c.add(1).add(2) 读起来就像把对象只写一次的 c.add(1); c.add(2);。如果这条链可能作用于 const 对象，就用 counter const & 配一个 const 成员函数（第13.3章）。

4. 情形 3：你指的是这个对象吗？

一个成员函数可以把它被调用的对象与另一个对象做比较。this 是前者的地址，&other 是后者的地址，所以 this == &other 问的是它们是不是同一个对象 — 而不是内容是否相等： 


bool same_as(counter const &other) const noexcept
{
	return this == &other;   // one object, addressed twice?
}

在 c.same_as(d) 里地址不同，答案是 0；在 c.same_as(c) 里两个名字指同一个对象，答案是 1。比较内容会是另一个函数：return value_ == other.value_;。两者都有用；请务必清楚你问的是哪个问题。

5. 在 const 成员函数里，this 是 const

这就是第13.3章背后的机制。关键字 this 跟随成员函数的 const： 


::std::int_least32_t value() const noexcept   // inside: this is counter const *
{
	return value_;                        // so value_ is const here too
}

因此 const 成员函数不能给成员赋值，也不能调用非 const 的成员函数 — 它持有的对象是只读的，通过它到达的每个成员也都是只读的。

this 在静态成员函数里不存在（第13.9章）。静态成员函数不是在对象上调用的，所以没有对象可指： 

error: 'this' is unavailable for static member functions

当然，它在自由函数里也不存在：


error: invalid use of 'this' in non-member function
不要滥用 this。在裸的 value_ 意思相同时写 this->value_，只是增加了读者必须过滤的噪音。当它能消除歧义（情形 1）、当它就是你需要的那个值（情形 2 和 3）、或者当只有代码编辑器的语法着色才能区分你的成员时 — 才写它，而后者是任何读者都看不见的。
