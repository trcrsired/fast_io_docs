第12.5章: 安全性考量

English

为什么这些随机源是安全的

ibuf_white_hole_engine 与平台专用的随机源适合密码学用途，因为它们：

  • 读取 OS 熵源：它们使用操作系统的密码学安全随机数生成器，后者从硬件来源（时序抖动、硬件随机数发生器等等）收集熵。
  • 不可预测：即使攻击者观察到了此前的全部输出，也无法预测未来的输出。
  • 没有隐藏状态：不存在可被攻破的全局状态。每个引擎实例相互独立，而且线程安全。
  • 安全清空内存：引擎销毁时内部缓冲区被擦除，保护密码学密钥材料不被内存转储获取。

什么时候使用

  • 生成密码学密钥
  • 创建安全的 token 与会话 ID
  • 为密码加盐
  • 为仿真或游戏的伪随机引擎播种
  • 任何安全敏感的应用

什么时候不该直接使用

  • 高性能应用：当你每秒需要数以百万计的随机数时，请改用从安全源播种的 ::std::mt19937 这类快速伪随机引擎。
  • 可复现的结果：当你需要为调试或测试重现同一序列时，请使用固定种子（保存到文件）的已播种伪随机引擎。

常见错误：取模偏差

绝不要用取模（value % range）来生成区间内的随机数。这会因鸽笼原理造成有偏分布。

请始终使用 ::std::uniform_int_distribution 或 <random> 中的其他分布。分布使用拒绝采样，保证区间内每个值的概率完全相同。

详见第12.2章: 分布： 分布才是把"均匀随机的引擎"变成"均匀随机的区间"的东西， 而用手写 % 去完成这件事，正是偏置的来源。

要点

  • ibuf_white_hole_engine 是密码学安全的，适合密码学应用。
  • 用它生成密钥、token、密码，以及任何安全敏感的应用。
  • 对高性能或可复现的需求，用来自安全引擎的 ::std::seed_seq 为快速伪随机引擎播种。
  • 绝不要用取模生成区间内的数值 — 请使用分布。
  • 引擎销毁时会安全清空缓冲区，保护敏感数据。
