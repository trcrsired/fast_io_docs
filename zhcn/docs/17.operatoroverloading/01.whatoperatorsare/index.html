第17.1章 运算符就是函数

English

1. 精确地陈述这个替换

一个运算符表达式就是换了一种写法的函数调用。编译器先把它改写，然后做普通的候选函数匹配：

你写 编译器调用
a + boperator+(a, b)
a += ba.operator+=(b)
-aoperator-(a)
a[i]a.operator[](i)
a(b, c)a.operator()(b, c)
a == boperator==(a, b)；C++20 起如果它唯一存在， 也会用反序的 a.operator==(b)
delete p先 p->~T()，再 operator delete(p)（第18.1章）

立刻可以看出两个后果。第一，运算符的查找方式和普通函数完全一样：成员版本要求左操作数属于这个类； 非成员版本靠实参相关查找在操作数所在的命名空间里找到它。第二， 运算符可以显式按名字调用，你可以用它向自己证明没有任何魔法发生。

2. 完整例子：规范形状

每个算术值类型都该遵循这个形状：复合赋值是原语，它修改对象并返回引用； 二元运算符在它之上定义，按值接收操作数并返回一个新值。 


#include <fast_io.h>
#include <cstdint>

namespace money_ns
{

struct money
{
	::std::int_least64_t cents{};

	constexpr money &operator+=(money other) noexcept
	{
		cents += other.cents;
		return *this;
	}
};

[[nodiscard]] inline constexpr money operator+(money a, money b) noexcept
{
	return a += b;
}

}

int main()
{
	try
	{
		using money_ns::money;
		money const a{1250};
		money const b{375};
		::fast_io::io::println("a + b        = ", (a + b).cents);
		::fast_io::io::println("operator+(a,b)= ", operator+(a, b).cents);
		money c{a};
		c += b;
		::fast_io::io::println("c += b       = ", c.cents);
	}
	catch throws (::std::error e)
	{
		::fast_io::io::print("error: ");
		::fast_io::io::println(e);
	}
}


a + b        = 1625
operator+(a,b)= 1625
c += b       = 1625

这二十五行里值得注意的地方全在下面：

  • operator+= 是成员，因为它的左操作数被修改，而且就是对象本身。 它返回 money& 而不是 void，这样 a = b += c 保持它在 int 上的含义。
  • operator+ 是同一命名空间里的非成员。它按值接收两个操作数， 在左操作数的副本上做加法然后返回它 —— 这个副本会被消除或被移动， 所以这是最便宜的正确写法。因为它是非成员，money{1} + money{2} 以及任何一侧的隐式转换都是对称的（见 第17.3章）。
  • 两个都是 constexpr 和 noexcept：两个整数相加不会失败， 所以这个类型也不能假装它会失败 （第6.16章）。
  • operator+ 上的 [[nodiscard]] 会抓住 a + b; 这种当语句用的写法 —— 丢弃结果几乎一定是 bug。
  • main 里的 operator+(a, b) 是同一个函数。没有另一套机制。

3. 你做不到的事

这个特性比人们想象的要窄。除非至少有一个操作数是类或枚举类型，否则你不能重载运算符： 


int operator+(int a, int b) { return a * b; }


error: ‘int operator+(int, int)’ must have an argument of class or enumerated type

你也不能发明一个不存在的运算符，所以没有 **、没有 <>、 没有 &&&： 


s operator**(s a, s b) { return a; }


error: expected initializer before ‘*’ token

你不能改运算符的元数、结合性或者优先级：对你的类型，a + b * c 照样按 a + (b * c) 分组，a.b.c 也不能被重新定义成乘法。 你也不能重载 ::、.、.*、?:、 sizeof、alignof、typeid， 或者除“到某个类型”之外的转换。

最后这条限制正是运算符重载可以安全推理的原因：a + b * c 这样的表达式对程序里的每个类型都表示同一个形状， 所以读者解析表达式时永远不需要被告知你的类。本章警告的一切都在这个形状内部： 标点是固定的，但它的含义不是，麻烦就住在那里。

4. 成员还是非成员？

运算符 必须是成员 必须是非成员 可自由选择时，倾向
=、[]、()、-> 是
<<、>>（当作流 I/O 用） 成员 —— 除非你在搞 iostream，而你没有 （第17.6章）
+= -= *= /= 这一类 成员：它们修改对象
+ - * / == <=> 非成员：对称，而且两侧的隐式转换都成立
operator T() 是 根本不要写（第17.6章）

实践里唯一重要的理由是对称性：2 * v 调用的是 operator*(int, vec2)，它只能是非成员；而 v * 2 两种写法都行。 如果 v * 2 能编译而 2 * v 不能， 你就把一个实现选择泄漏到了类型的接口上。

5. 经验法则

  • 先写复合赋值，再拿它定义二元运算符。这保证两者永不打架。
  • 二元运算符按值接收操作数、按值返回。这不是悲观，这正是拷贝消除的前提。
  • 你写的每个运算符都是函数，所以它需要契约：noexcept 或 throws，不许有异常。
  • 返回值的运算符一律标 [[nodiscard]]。
  • 如果运算符的结果不是显然的数学结果 —— 如果它会分配、会失败、只在某些时候适用 —— 就停在这里去读 第17.2章： 你要的是命名函数。
