第26.12章：线程与可加锁流

English

1. 线程安全不是进程安全

一个进程内部的互斥量不能串行化另一个进程。可加锁流类型保护的是共享同一个对象的线程； 它们不会让两个独立进程写同一个文件变得安全。

性质 含义 由谁提供
线程安全 两个线程通过同一个对象调用时不会交错或破坏状态。 可加锁流别名或外部互斥量。
进程安全 两个进程写同一个文件时不会互相破坏。 操作系统，而且只对它定义为原子的操作；用户态互斥量做不到。

缓冲会让这个区分更尖锐。带缓冲流可能把一次逻辑写拆成多次刷新， 另一个进程可以在中间写入。需要进程级追加保证时， 用平台原子追加模式打开不带缓冲的 native 文件，或者用文件锁协调。

2. 可加锁别名

每个带缓冲文件家族都有可加锁别名。别名行为与基础类型相同， 但每次 print、scan 或 println 调用都会在调用期间 获取内部互斥量。

别名 基础类型 方向
ibuf_file_lockable ibuf_file 输入
obuf_file_lockable obuf_file 输出
iobuf_file_lockable iobuf_file 双向

字符变体遵循同样的命名：wibuf_file_lockable、 u8obuf_file_lockable、u16iobuf_file_lockable、 u32iobuf_file_lockable 等。通用名字是 basic_ibuf_file_lockable、basic_obuf_file_lockable 和 basic_iobuf_file_lockable。 


::fast_io::obuf_file_lockable out{"shared.txt"};

auto writer = [&out](int id)
{
    for (int i{}; i < 100; ++i)
    {
        ::fast_io::io::println(out, "thread ", id, " line ", i);
    }
};

互斥量让每次 println 相对于同一对象上的其他调用是原子的。 它不会让一串调用成为原子；另一个线程可以在它们之间运行。

3. 多调用临界区

多个调用必须表现为一个不中断的块时，在块外锁一次。 native_mutex 是 fast_io 的平台互斥量；io_lock_guard 是 RAII 守卫。 


::fast_io::obuf_file out{"shared.txt"};
::fast_io::native_mutex mtx;

auto writer = [&](int id)
{
    for (int i{}; i < 100; ++i)
    {
        ::fast_io::io_lock_guard guard{mtx};
        ::fast_io::io::print(out, "thread ");
        ::fast_io::io::print(out, id);
        ::fast_io::io::print(out, " line ");
        ::fast_io::io::println(out, i);
    }
};

这保护整个四次调用序列。守卫在作用域退出时解锁，包括 I/O 操作抛出时。 不要在你无法控制的阻塞操作期间持有守卫；那会把互斥量变成全局停顿。

4. 互斥量类型

::fast_io::native_mutex 解析为平台原语：

平台 实现
带 pthread 的 POSIX pthread_mutex_t
现代 Windows SRW 锁
旧 Windows 临界区
mcfgthread 目标 _MCF_mutex
单线程 / WASI / 无 pthread 空操作互斥量

可加锁别名内部使用 native_mutex。需要可移动包装时用 native_mutex_movable（头文件侧）；普通类型在某些平台上可能不可移动。

5. 选择正确的工具

场景 使用
一次 println 不能与另一次交错 *_lockable 别名
一组调用必须表现为一个块 native_mutex + io_lock_guard
多个进程追加同一个文件 OS 级原子追加、文件锁或专用 logger；不是用户态互斥量
高吞吐日志 每线程缓冲加单写者，或异步队列
只读共享文件 没人写的话不需要互斥量

6. 模块与头文件边界

fast_io 模块导出 native_mutex、可加锁别名及其字符变体。 io_lock_guard 目前在头文件侧，需要时包含 <fast_io.h>。可加锁别名本身在模块的 device.inc 导出列表里。

不要把两种锁混在一起。 可加锁流拥有一个互斥量； io_lock_guard 锁的是你自己的互斥量。 在调用可加锁流时再套一个 native_mutex 通常没必要； 给普通文件加锁也不会让它变成可加锁类型。

要点

  • 可加锁流提供单进程内的线程安全，不是进程安全。
  • ibuf_file_lockable、obuf_file_lockable 和 iobuf_file_lockable 按调用加锁。
  • 用 native_mutex + io_lock_guard 保护多调用临界区。
  • native_mutex 映射为 pthread mutex、SRW 锁、临界区、 mcfgthread mutex 或空操作互斥量。
  • 缓冲可能把一次逻辑写拆成多次刷新；进程级原子性需要 OS 支持或文件锁。
  • io_lock_guard 在头文件侧；可加锁别名和 native_mutex 由模块导出。
