第26.21章：加密与 TLS

English

1. 两个模块

原语加密在 fast_io_crypto；TLS record 层和 socket 包装在 fast_io.tls。TLS 模块导入 crypto 模块。两者都不属于总括 fast_io 模块。

模块 导出
fast_io_crypto CRC32/CRC32C、AES-128/192/256、Ed25519、X25519、NIST 椭圆曲线和 ECDSA 辅助。
fast_io.tls TLS 客户端配置、TLS 客户端、socket 文件、根证书库、对端证书、 平台后端、握手操作。

2. CRC32

crc32_context 和 crc32c_context 是增量哈希上下文： 


::fast_io::crc32c_context crc;
crc.update(data, data + size);
auto const value{crc.digest_value()};
成员 含义
update(first, last)喂入一段字节。
reset()重新开始上下文。
digest_value()返回 32 位摘要。
digest_to_byte_ptr(ptr)按线格式字节序写摘要。
do_final()空的收尾钩子。

平台有硬件 CRC 指令时使用硬件，否则用查表回退。上下文是 constexpr。

3. AES

aes_ctx<key_size> 接收原始密钥，按 16 字节块做 ECB 运算。 别名是 aes128、aes192 和 aes256。 


::fast_io::aes128 cipher{key_bytes.data()};
cipher.encrypt(plain, nblocks, ciphertext);
cipher.decrypt(ciphertext, nblocks, plain);

一个上下文同时服务两个方向；解密反向复用加密 key schedule。 块循环在后端内部，from/to 可以重叠。

ECB 不是加密方案。 这个 API 是原始块原语。 真实协议需要模式、nonce/IV、认证和密钥分离。用 TLS 或头文件层的 AEAD 构造； 不要用 ECB 自己拼模式。

4. Ed25519 与 X25519

ed25519 和 diffie_hellman::x25519 暴露固定大小的 std::byte span 或裸指针操作。裸指针形式以 _to_ptr 结尾。

操作 含义
ed25519::create_key_pair(...)从 32 字节 secret 生成 公钥/私钥对。
ed25519::sign_message(...)为消息生成 64 字节签名。
ed25519::verify_signature(...)布尔验签。
x25519::calculate_public_key(...)从 32 字节 secret 计算 公钥。

_to_ptr 和 span 重载等价；span 形式在类型层强制固定大小。 blinding 重载接受显式 blinding 上下文。导出的 X25519 表面计算公钥； 共享密钥构造属于协议层，不是单独导出的辅助。

5. NIST 曲线与 ECDSA

ecc::secp256r1、secp384r1 和 secp521r1 是导出的曲线类型。模块还导出 ECDSA 验签、签名、RFC 6979 确定性签名和 RFC 6979 DRBG。

这些是底层算术和签名原语。它们不管理密钥、不选择哈希， 也不决定哪条曲线适合某个协议。完整握手用 TLS 层。

6. TLS 类型

类型 角色
tls_client_config主机名、信任锚、hostname/chain 检查和 内核 offload 偏好。
tls_clientsocket observer 上的 TLS 状态。
tls_socket_file拥有 socket + TLS 客户端组合。
iobuf_tls_socket_file带缓冲 TLS socket，用于 print/scan。
root_store从 PEM 解码的 DER 信任锚。
peer_certificates解析后的对端证书链存储。
native_tls_socket_file平台 TLS 后端（配置时 SChannel 或 OpenSSL/GnuTLS）。

tls_socket_file 拥有 socket；tls_socket 借用 observer。 TLS 流仍然是设备：握手之后用 print、scan 和 transmit。

7. 握手与信任


::fast_io::tls::tls_socket_file tls{std::move(sock)};
::fast_io::operations::handshake(tls, ::fast_io::u8cstring_view{u8"example.com"});
::fast_io::io::println(tls, "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n");

hostname 重载加载系统信任库、检查链并验证主机名。自定义 bundle 时， 从 root_store 填 tls_client_config， 再调用 config 重载的 handshake。

信任加载器（root_store_load_system、 root_store_load_pem_file）在头文件侧。TLS 模块导出类型和握手操作， 不导出字符串路径 loader。

8. 后端与边界

fast_io.tls 可以使用自己的用户态 record 层、OS 后端 （Windows 上 SChannel、平台原生 TLS）或构建时启用的 OpenSSL/GnuTLS 后端。 tls_default_crypto 选择平台默认；config 和 socket 类型不变。

头文件侧额外内容：SHA-1/SHA-256/SHA-512、HMAC、MD5、RSA、AEAD 构造、 padding 和平台 crypto 后端。它们还没有进入 fast_io_crypto 模块导出列表。

不要把原语当协议。 AES-ECB、裸签名调用和裸 X25519 结果都是积木。 安全协议需要密钥派生、nonce、认证、transcript 绑定和错误处理；TLS 层已经有了。

要点

  • 原语加密在 fast_io_crypto；TLS 在 fast_io.tls。
  • CRC32/CRC32C 上下文是增量且 constexpr 的。
  • AES 是原始 16 字节 ECB 块原语；不是完整加密方案。
  • Ed25519 和 X25519 有 span 和 _to_ptr 形式。
  • NIST 曲线和 ECDSA 辅助是底层；TLS 提供完整握手。
  • TLS socket 文件是设备；握手后 print/scan 可用。
  • hostname 握手加载系统信任库；自定义 bundle 用 tls_client_config。
  • SHA/HMAC/RSA/AEAD/padding 和平台后端仍在头文件侧。
