第26.14章：网络

English

1. socket 是设备

fast_io 没有独立的 socket 流层次。socket 是设备，同样的 print、scan、read、write 和 transmit 操作都适用。网络层只负责创建句柄和转换地址。

类型 角色 模块
native_socket_file 拥有的原生 socket 句柄；不带缓冲。 fast_io
iobuf_socket_file 带缓冲 socket；格式化 TCP I/O 的常规类型。 fast_io
native_dns_file 拥有某个主机名的 DNS 结果集。 fast_io
ip、ipv4、ipv6 地址与端口值类型。 fast_io
net_service RAII 网络子系统守卫（Windows 上 WSA；POSIX 上 SIGPIPE 策略）。 头文件侧

在 POSIX 上 socket 就是文件描述符，所以 native_socket_file 和 native_file 是同一类型，iobuf_socket_file 和 iobuf_file 也是同一类型。在 Windows 上 socket 是独立句柄， 所以 socket 类型是分开的。

2. TCP 辅助

条目 签名 含义
tcp_connect tcp_connect(ip, open_mode = {}) 创建已连接的 TCP socket。
tcp_connect tcp_connect(ipv4, open_mode = {})、 tcp_connect(ipv6, open_mode = {}) 指定地址族的形式。
tcp_listen tcp_listen(std::uint_least16_t port, open_mode = {}) 端口上的双栈 listener。
tcp_listen tcp_listen(ipv4, open_mode = {})、 tcp_listen(ipv6, open_mode = {}) 把 listener 绑定到特定地址。 

auto listener{::fast_io::tcp_listen(8080u16)};
::fast_io::native_socket_file conn{::fast_io::posix_accept(listener)};
::fast_io::iobuf_socket_file buf_conn{::fast_io::io::transmit(conn)};

tcp_listen 让 socket 保持监听模式；tcp_connect 返回一个工厂，交给拥有 socket 文件。异步层用 open_mode::no_block 选择非阻塞 socket。

3. DNS

native_dns_file 拥有解析结果。可以迭代所有地址， 或者调用 to_ip(dns, port) 取第一个结果并附加端口。 


::fast_io::native_dns_file dns{u8"example.com"};
::fast_io::iobuf_socket_file sock{
    ::fast_io::tcp_connect(::fast_io::to_ip(dns, 80u16))};
条目 含义
native_dns_file(host) 解析 UTF-8 主机名。
to_ip(dns, port) 第一个解析地址加给定端口。
to_ip_address(dns) 第一个解析地址，不带端口。
begin(dns) / end(dns) 迭代所有解析条目。

解析器不会无限重试，也不会在背后替你挑“最好”的地址。 主机同时有 IPv4 和 IPv6 记录时，迭代结果集。

4. socket 自由函数

底层操作镜像 POSIX 名字，并作用于 socket observer：

操作 含义
posix_connect(sock, addr, len)连接对端。
posix_bind(sock, addr, len)绑定本地地址。
posix_listen(sock, backlog)让已绑定 socket 进入监听模式。
posix_accept(listener)接受一个连接。
posix_recvfrom、posix_sendto数据报收发。
posix_setsockopt、posix_getpeernamesocket 选项和对端地址。

这些是头文件侧。上面的 TCP 辅助是可移植路径；自由函数用于需要原始地址或选项的协议工作。

5. net_service

在 Windows 上，任何 socket 操作之前必须先初始化网络子系统。 net_service 在构造函数里执行 WSAStartup， 析构函数里执行 WSACleanup。在 POSIX 上它是空操作对象， 为了可移植性保留。

在 POSIX 上，net_service 还控制 SIGPIPE 策略。 默认忽略 SIGPIPE，这样写已关闭的对端会返回错误，而不是终止进程。 posix_no_ignore_sigpipe 标志保留默认处置。 


::fast_io::net_service net_svc;

在 main 开头创建一个，并让它活到程序的网络生命周期结束。 不要在短命的 worker 作用域里创建它。

6. 协议支持

socket API 是操作系统 socket 接口的薄包装。受支持的协议清单是 OS 清单， 不是 fast_io 清单：

  • TCP 和 UDP。
  • POSIX 上的 Unix 域 socket。
  • OS 支持时的蓝牙 socket。
  • 原始 socket（通常需要提升权限）。
  • OS socket API 暴露的其他 family。

TCP 和 UDP 有便捷辅助。其他 family 从原生 socket 句柄和原始地址结构构造。

7. 模块与头文件边界

fast_io 模块导出 native_socket_file、 iobuf_socket_file、native_dns_file、to_ip、 to_ip_address、ip、ipv4、ipv6 和地址类型。net_service、tcp_connect、 tcp_listen 和原始 posix_* socket 自由函数目前在头文件侧。

不要混用 socket 和文件拥有者。 accepted socket 是原生句柄。 用 native_socket_file 包装就是转移所有权； 再次包装同一个句柄会双重关闭。

要点

  • socket 是设备；print、scan 和 transmit 原样适用。
  • native_socket_file 不带缓冲；iobuf_socket_file 是格式化 TCP 类型。
  • tcp_connect 和 tcp_listen 是可移植 TCP 辅助。
  • native_dns_file 拥有解析结果；to_ip 选一个并附加端口。
  • net_service 是 RAII 网络守卫和 POSIX SIGPIPE 策略对象。
  • 协议集合是 OS socket 集合；原始 socket 和部分 family 需要权限。
  • net_service、TCP 辅助和原始 socket 函数在头文件侧； socket、DNS 和地址类型由模块导出。
