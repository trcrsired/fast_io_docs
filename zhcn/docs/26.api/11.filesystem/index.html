第26.11章：文件系统与 OS 层

English

1. 两类 API

本页覆盖两个相关表面。文件系统表面遍历目录， 并相对目录句柄打开条目。OS 层表面暴露各平台的原生文件类型： POSIX 文件描述符、Win32 句柄、NT 句柄和 Wine 宿主描述符。

它们共享一条规则：目录句柄或原生句柄是拥有者；entry、observer 或 at_entry 是借用。借用不能比锚定它的句柄活得久。

2. 目录句柄与条目

名字 角色 模块
dir_file 拥有的目录句柄。打开路径，析构时关闭。 fast_io
dir_io_observer 目录句柄的非拥有视图。 fast_io
at(df) 锚定在目录上的 at_entry；相对打开和遍历的基址。 fast_io
current(at(df)) 直接子条目的范围。 fast_io
recursive(at(df)) 所有后代的范围。 fast_io 

::fast_io::dir_file df(u8"data");

for (auto const &ent : ::fast_io::current(::fast_io::at(df)))
{
    if (::fast_io::is_dot(ent)) continue;
    println(::fast_io::mnp::code_cvt(::fast_io::u8filename(ent)));
}

3. 目录条目函数

函数 返回 模块
u8filename(ent) UTF-8 文件名视图。 fast_io
u8extension(ent) UTF-8 扩展名视图。 头文件侧
u8stem(ent) 去掉扩展名的 UTF-8 文件名。 头文件侧
native_filename(ent) 平台原生编码的文件名。 头文件侧
type(ent) file_type。 头文件侧
is_dot(ent) 对 . 和 .. 为真。 fast_io
drt(ent) 用于打开该条目的 (目录句柄, 名字) 对。 头文件侧

file_type 区分 regular、directory、 symlink、block、character、fifo、 socket、unknown 和 not_found。 


for (auto const &ent : ::fast_io::current(::fast_io::at(df)))
{
    if (::fast_io::is_dot(ent)) continue;
    if (::fast_io::type(ent) == ::fast_io::file_type::regular)
    {
        ::fast_io::native_file_loader loader(::fast_io::drt(ent));
        println(::fast_io::mnp::code_cvt(::fast_io::u8filename(ent)),
                ": ", loader.size(), " bytes");
    }
}

4. 相对目录打开

锚定在 at_entry 上的相对打开，避免构造完整路径， 也避免“先检查路径再打开”的竞态。模式在所有平台上相同： 用 at(df) 和相对名字构造文件类型。 


::fast_io::dir_file df(u8"data");
::fast_io::native_file f(::fast_io::at(df), u8"record.bin",
                         ::fast_io::open_mode::in);

at(ent) 锚定在特定目录条目上，drt(ent) 给出 文件构造函数和 loader 接受的 (handle, name) 对。 遍历发现文件后，这是首选打开方式。

5. 临时文件

::fast_io::io_temp 是标签，不是类型。把它传给任何拥有文件的构造函数。 文件在系统临时目录创建，对象销毁时删除： 


::fast_io::iobuf_file tmp{::fast_io::io_temp};
println(tmp, "scratch data");

它适用于 native_file、obuf_file、iobuf_file、 c_file 和其他拥有文件类型。删除绑定在对象生命周期上， 不是单独的清理调用。io_temp 是头文件侧，目前不在模块导出列表里。

6. 原生 OS 层

类型 平台 句柄 模块
posix_file POSIX 文件描述符 fast_io
win32_file Windows HANDLE fast_io
nt_file Windows NT API NT HANDLE fast_io
zw_file Windows NT API NT HANDLE fast_io
wine_file POSIX 上的 Wine 宿主描述符 头文件侧
c_file C stdio FILE* fast_io_legacy
filebuf_file C++ iostream basic_filebuf* fast_io_legacy

需要平台自己的句柄、flags 或错误语义时用原生层。否则用带缓冲别名， 它隐藏平台差异。层关系记录在 第11.17章。

包装已有句柄是显式的：拥有类型接管并关闭它；观察者类型借用且不关闭。 不要为同一个句柄同时构造两者。

7. 内存映射与文件 loader

native_file_loader 映射文件并暴露其字节，不需要读循环。 加载大型只读文件时首选它： 


::fast_io::native_file_loader loader("big.bin");
auto *data{loader.data()};
auto size{loader.size()};

loader 拥有映射，析构时释放。平台没有可用映射时，它退回具有相同可观察 API 的 allocation loader。需要可写映射或显式 flags 时，用平台 mmap 选项和 allocation_file_loader 家族；教程细节在 第11.8章。

8. 模块与头文件边界

fast_io 模块导出 dir_file、at、 current、recursive、u8filename、 is_dot、file_type、posix_file_status、 native_file_loader，以及平台文件类型 posix_file、win32_file 和 nt_file。 u8extension、u8stem、native_filename、 type 和 drt 等条目辅助目前在头文件侧。

不要为一个句柄混用拥有者。 如果构造函数接管了原生句柄， 句柄现在就归那个对象所有。再用另一个拥有者包装会导致双重关闭。 只需要借用时用 observer。

要点

  • dir_file 拥有目录；at_entry 和 entry 从它借用。
  • at、current 和 recursive 是遍历原语。
  • u8filename 和 is_dot 由模块导出； 扩展名、stem、原生名字和 drt 在头文件侧。
  • 相对 at(df) 或 drt(ent) 打开条目，不要重建完整路径。
  • io_temp 是任何拥有文件构造函数的标签；对象死亡时删除文件。
  • 原生文件类型暴露平台句柄；带缓冲别名隐藏平台。
  • native_file_loader 映射文件，而不是复制进缓冲区。
