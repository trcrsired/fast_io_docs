第11.11章: C 风格 I/O

English

概述

C 围绕 FILE* 提供了一整套 I/O 设施，以及 fopen、fclose、printf、scanf、fprintf 和 fscanf 这些函数。它们是 C 与 C++ 生态中最古老、使用最广的 I/O 原语。

fast_io 包装了 C 的 FILE* 接口，让你能在保持 RAII 语义、类型安全和性能的同时使用 print/println/scan。

错误处理的问题

C stdio 最大的问题之一是大多数函数都可能失败，而正确的错误处理要求你检查大多数调用的返回值： 


#include <stdio.h>

int main() {
    FILE *fp = fopen("output.txt", "w");
    if (fp == NULL) {
        perror("fopen failed");
        return 1;
    }

    if (fprintf(fp, "%s", "Hello\n") < 0) {
        perror("fprintf failed");
        fclose(fp);
        return 1;
    }

    // fclose can fail, but there's nothing you can do about it
    fclose(fp);

    return 0;
}

这极其容易出错。大多数 C 程序不检查 fprintf 的错误，甚至连 printf 自己都不检查。printf 也可能失败（例如管道断开、磁盘满、I/O 错误），但几乎没有人检查它的返回值。

fast_io 让错误处理变得显式。函数默认在出错时抛出异常，或者返回你无法不小心忽略的错误码。这使写出有 bug 的 I/O 代码难得多。

标准 C I/O：<cstdio>

在讨论 fast_io 如何包装 C I/O 之前，先回顾标准 C I/O API 本身。所有 C I/O 函数都声明在 <cstdio>（C 中是 <stdio.h>）中。核心抽象是 FILE*，一个不透明指针，指向表示已打开文件、管道或设备的流。

打开与关闭文件


#include <cstdio>

int main()
{
    try
    {
        // Open a file for writing
        FILE* fp = std::fopen("output.txt", "w");
        if (!fp) {
            return 1;  // Failed to open
        }

        // ... use the file ...

        // Always close when done
        std::fclose(fp);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

模式串控制文件如何打开：

  • "r" — 读（文件必须存在）
  • "w" — 写（创建或截断）
  • "a" — 追加（创建或追加）
  • "r+" — 读写（文件必须存在）
  • "w+" — 读写（创建或截断）
  • "a+" — 读取并追加（创建或追加）
  • 加 "b" 表示二进制模式："rb"、"wb" 等。

格式化输出：printf、fprintf


#include <cstdio>

int main()
{
    try
    {
        int x = 42;
        double pi = 3.14159;
        char const* name = "Alice";

        // printf: write to stdout
        std::printf("%s%s%s%d%s%.2f%s", "Name: ", name, ", Age: ", x, ", Pi: ", pi, "\n");

        // fprintf: write to a FILE*
        FILE* fp = std::fopen("data.txt", "w");
        std::fprintf(fp, "%s%d%s%f%s", "x = ", x, ", pi = ", pi, "\n");
        std::fclose(fp);

        // sprintf: write to a string buffer
        char buffer[100];
        std::sprintf(buffer, "%s%d", "Value: ", x);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

常见格式说明符：

  • %d 或 %i — 有符号整数
  • %u — 无符号整数
  • %x、%X — 十六进制（小写/大写）
  • %o — 八进制
  • %f — 浮点（十进制记法）
  • %e、%E — 浮点（科学计数法）
  • %g、%G — 浮点（最短表示）
  • %s — 字符串
  • %c — 字符
  • %p — 指针
  • %% — 字面的 %

格式化输入：scanf、fscanf


#include <cstdio>
#include <memory>

int main()
{
    try
    {
        int x;
        double y;

        // scanf: read from stdin
        std::fputs("Enter two numbers: ", stdout);
        std::scanf("%d%lf", ::std::addressof(x), ::std::addressof(y));

        // fscanf: read from a FILE* (format string has only specifiers)
        FILE* fp = std::fopen("data.txt", "r");
        std::fscanf(fp, "%d%lf", ::std::addressof(x), ::std::addressof(y));  // Input file should contain: 42 3.14
        std::fclose(fp);

        // sscanf: read from a string
        char const* input = "42 3.14";
        std::sscanf(input, "%d%lf", ::std::addressof(x), ::std::addressof(y));
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

警告：scanf 家族极其危险，应当避免使用。问题包括：

  • %s 导致缓冲区溢出（改用 fgets）
  • 格式串漏洞（CWE-134：使用外部可控的格式串）：若格式串由用户控制，攻击者可以读写任意内存
  • 错误处理困难（检查返回值很复杂）
  • 空白字符处理令人困惑且易错
  • 数值输入没有边界检查

请改用 ::fast_io::io::scan，它类型安全、显式处理错误，并且免疫这些问题。

printf 格式说明符的复杂度

printf 家族有一套极其复杂的格式说明符语法。摘自 cppreference，格式说明符包括：

  • 类型说明符：%d、%i、%u、%x、%X、%o、%f、%F、%e、%E、%g、%G、%a、%A、%s、%c、%p、%n
  • 长度修饰符：h、hh、l、ll、j、z、t、L
  • 标志：-、+、 、#、0
  • 宽度与精度：%10d、%.2f、%10.2f、%*d

像 %#0+10.5lld 这样的组合是合法的，但几乎不可能记住。这种复杂度让 printf 极易出错：

  • 类型说明符与实参类型不符（例如对 long 用 %d）
  • 长度修饰符写错（例如 long 漏了 l）
  • 忘记为浮点指定精度
  • 混淆相近的说明符（%x 与 %X、%f 与 %e）

大多数程序员无法正确记住所有这些规则。这就是格式串 bug 和 I/O 缓冲区溢出成为最常见安全漏洞的原因之一。几乎所有命令行 I/O 缓冲区漏洞都来自 stdio 的误用。

fast_io 彻底消除了这种复杂度。没有需要记住的格式串。库会根据实参类型自动确定正确的格式化方式，从而不可能出现类型与格式说明符不匹配。

字符与行 I/O


#include <cstdio>

int main()
{
    try
    {
        FILE* fp = std::fopen("example.txt", "r");

        // Read a single character
        int ch = std::fgetc(fp);

        // Read a line (up to n-1 characters or newline)
        char buffer[256];
        std::fgets(buffer, sizeof(buffer), fp);

        // Write a single character
        std::fputc('A', stdout);

        // Write a string
        std::fputs("Hello, World!\n", stdout);

        std::fclose(fp);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

二进制 I/O


#include <cstdio>

int main()
{
    try
    {
        // Write binary data
        FILE* fp = std::fopen("data.bin", "wb");
        int numbers[] = {1, 2, 3, 4, 5};
        std::fwrite(numbers, sizeof(int), 5, fp);
        std::fclose(fp);

        // Read binary data
        fp = std::fopen("data.bin", "rb");
        int buffer[5];
        std::size_t count = std::fread(buffer, sizeof(int), 5, fp);
        std::fclose(fp);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

标准流

C 提供三个预定义的流：

  • stdin — 标准输入（通常是键盘）
  • stdout — standard output (usually terminal)
  • stderr — 标准错误（通常是终端，不带缓冲）

#include <cstdio>

int main()
{
    try
    {
        std::fputs("This goes to stdout\n", stdout);
        std::fputs("This goes to stderr\n", stderr);

        // printf() is equivalent to fputs(..., stdout)
        std::fputs("Same as stdout\n", stdout);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

在 fast_io 中使用 C 文件

fast_io 为 FILE* 提供 RAII 包装，这样你就能在 C 文件上使用 print/println/scan，同时确保资源管理正确。

::fast_io::c_file：RAII 包装

::fast_io::c_file 包装一个 FILE*，并在对象离开作用域时自动关闭它。这可以防止资源泄漏。 


#include <fast_io.h>
#include <fast_io_device.h>

int main()
{
    try
    {
        using namespace ::fast_io::iomnp;

        // Open a file for writing (RAII)
        ::fast_io::c_file cf(u8"output.txt", ::fast_io::open_mode::out);

        // Use fast_io's print/println
        println(cf, "Hello, " "World!"
            "The answer is: ", 42);

        // File is automatically closed when cf goes out of scope
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

mode 参数与 fopen 的用法相同：

  • ::fast_io::open_mode::in — 读
  • ::fast_io::open_mode::out — 写（创建或截断）
  • ::fast_io::open_mode::append — 追加
  • 用 | 组合：::fast_io::open_mode::in | ::fast_io::open_mode::out
  • 加 ::fast_io::open_mode::binary 表示二进制模式

从 C 文件读取


#include <fast_io.h>
#include <fast_io_device.h>

int main()
{
    try
    {
        using namespace ::fast_io::iomnp;

        // Open for reading
        ::fast_io::c_file cf(u8"data.txt", ::fast_io::open_mode::in);

        // Read values
        int x;
        double y;
        ::fast_io::string name;

        scan(cf, x);
        scan(cf, y);
        scan(cf, ::fast_io::mnp::str_line_get(name));  // read a line

        println("x = ", x, "\n"
          "y = ", y, "\n"
          "name = ", name);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

::fast_io::c_io_observer：非拥有视图

有时你的 FILE* 来自别处（例如作为参数传入），而你想在不接管所有权的情况下使用 fast_io 的 API。这时用 ::fast_io::c_io_observer： 


#include <fast_io.h>
#include <fast_io_device.h>
#include <cstdio>

void process_file(::fast_io::c_io_observer observer) throws {
    using namespace ::fast_io::iomnp;
    // Use fast_io's API without taking ownership
    print(observer, "Processing...\n");
}

int main()
{
    try
    {
        // Open with C API
        FILE* fp = std::fopen("data.txt", "w");
        ::fast_io::c_file cf(fp);
        // Wrap it in an observer (non-owning)
        ::fast_io::c_io_observer observer{fp};

        process_file(observer);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

观察者离开作用域时不会关闭文件 — 那是原所有者的责任。

访问底层的 FILE*

你可以通过 .fp 成员访问底层的 FILE*： 


#include <fast_io.h>
#include <fast_io_device.h>
#include <cstdio>

int main()
{
    try
    {
        ::fast_io::c_file cf(u8"data.txt", ::fast_io::open_mode::out);

        // Use fast_io's API
        println(cf, "fast_io output");

        // Access the underlying FILE* for C API calls
        std::fprintf(cf.fp, "%s", "C API output\n");

        // File is closed automatically
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

线程安全：_unlocked 变体

C 的 FILE* 操作默认是线程安全的 — 每次操作都会获取内部的锁。但这可能很慢。fast_io 提供跳过内部锁的 _unlocked 变体： 


#include <fast_io.h>
#include <fast_io_device.h>

int main()
{
    try
    {
        using namespace ::fast_io::iomnp;

        // Unlocked variant (no internal locking)
        ::fast_io::c_file_unlocked cf(u8"data.txt", ::fast_io::open_mode::out);

        println(cf, "Fast, but not thread-safe by default");

        // If you need thread safety, use ::fast_io::native_mutex
        {
            ::fast_io::native_mutex_lock lock(cf);
            println(cf, "Thread-safe output");
        }
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

在下列情况下使用 c_file_unlocked：

  • 你处于单线程环境
  • 你用 ::fast_io::native_mutex 手动同步
  • 你需要最大性能，并且理解其线程含义

与 C 库互操作

许多 C 库要求 FILE* 参数。你可以把 c_file 或 c_io_observer 底层的 FILE* 传进去： 


#include <fast_io.h>
#include <fast_io_device.h>
#include <cstdio>

// C library function
void c_library_function(FILE* fp) throws {
    std::fprintf(fp, "%s", "From C library\n");
}

int main()
{
    try
    {
        ::fast_io::c_file cf(u8"data.txt", ::fast_io::open_mode::out);

        // Use fast_io
        println(cf, "From fast_io");

        // Pass to C library
        c_library_function(cf.fp);

        // More fast_io
        println(cf, "Back to fast_io");
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

要点

  • C stdio 要求你检查大多数函数调用的错误（不过 fclose 的失败通常无法恢复）。大多数代码忽略了这些错误，导致数据被悄悄丢失。
  • ::fast_io::c_file 用 RAII 包装 FILE* — 文件会被自动关闭。
  • ::fast_io::c_io_observer 是对已有 FILE* 的非拥有视图。
  • _unlocked 变体跳过内部加锁。需要时用 ::fast_io::native_mutex 手动同步它们。
  • 格式串只应包含格式说明符（%s、%d 等），不要包含别的东西。绝不要把字面文本、换行或其他字符放进格式串。把所有字面内容放进实参：用 printf("%s", "text\n")，而不是 printf("text\n") 或 printf("%s\n", "text")。更好的做法是：纯字符串用 fputs，类型安全输出用 ::fast_io::io::print。绝不要把用户可控的字符串当作格式串（CWE-134：使用外部可控的格式串）。
  • 把指针传给 scanf/fscanf/sscanf 时，始终用 ::std::addressof() 而不是 &。即使类型重载了 operator&，这样也能正确工作。
  • printf 的格式说明符极其复杂，几乎不可能正确记住（见 cppreference）。这种复杂度导致源源不断的 bug 与安全漏洞。
  • 优先使用 ::fast_io::io::print/println/scan 而不是 C 函数 — 它们类型安全、更快、显式处理错误，并且免疫格式串攻击。
