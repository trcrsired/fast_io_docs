第18.9章：虚继承与菱形

English

为什么单独一页

第18.2章讲普通的虚分派：vptr、vtable、间接调用。这一页讲另一个特性，它只是碰巧共用同一个关键字。 基类列表里的 virtual 是虚继承，它的存在是为了让多重继承共享一个 基类子对象，而不是复制它。

它不是更好的继承形式，也不是复用工具。它是针对一种特定形状的布局和生命周期机制：菱形。

1. 虚继承：菱形

基类列表里的 virtual 和函数上的 virtual 是两个不同的特性。它解决另一个问题： 多重继承可能把同一个公共基类的一份以上副本放进同一个对象。 

struct base
{
    int id{};
    virtual ~base() = default;
};

struct left : base
{
    int l{};
};

struct right : base
{
    int r{};
};

struct bottom : left, right
{
    int b{};
};

现在一个 bottom 对象包含两个 base 子对象：一个来自 left，一个来自 right。名字 id 有歧义，转换成 base& 也有歧义： 

bottom x;
// x.id = 1;            // error: ambiguous, which base?
// base &br = x;        // error: ambiguous base

left &l = x;
right &r = x;
base &bl = l;           // the base inside left
base &br = r;           // the base inside right

两个基类也有各自的状态。如果 base 里有一个 id，通过 bl 修改它不会通过 br 看到。对于真正的“是一个”菱形——一个共享的基类 子对象——把对 base 的继承声明为虚继承： 

struct left : virtual base
{
    int l{};
};

struct right : virtual base
{
    int r{};
};

struct bottom : left, right
{
    int b{};
};

现在 bottom 恰好有一个 base 子对象，由 left 和 right 两个分支共享。名字不再有歧义： 

bottom x;
x.id = 1;               // OK: one shared base
base &br = x;           // OK: one shared base
left &l = x;
base &bl = l;           // still refers to the same shared base

2. 布局与构造

代价在布局。虚基类不能在每个完整对象里都放在固定偏移，因为通向它的路径取决于最派生类型。实现通常给类 加一个指针或偏移表（virtual base pointer，或 vbptr），访问虚基类成员变成间接访问。 标准不规定布局；sizeof、偏移和隐藏指针的数量都是 ABI 细节。不要在这些东西上构建线格式。

另一个锋利边缘是构造顺序。虚基类先于非虚基类构造，最派生类负责初始化虚基类。当中间类不是最派生对象时， 它对虚基类的初始化器会被忽略： 

struct base
{
    base() { std::print("base\n"); }
};

struct left : virtual base
{
    left() : base{} { std::print("left\n"); }
};

struct right : virtual base
{
    right() : base{} { std::print("right\n"); }
};

struct bottom : left, right
{
    bottom() { std::print("bottom\n"); }
};

bottom x; // base, left, right, bottom

析构按相反顺序：bottom、right、left、base。 如果你写了一个假设自己控制虚基类的构造函数，要分别把它当独立对象和更派生对象的基类来测试。同一个构造函数 在这两种情况下可能看到不同的基类初始化。

3. 交叉转换与替代方案

兄弟分支之间的交叉转换需要 RTTI。从 left* 到 right* 的 static_cast 不允许，因为编译器在没有完整对象时不知道偏移。dynamic_cast 可以找到共享基类或兄弟子对象，但它要求多态类型和一次运行时搜索： 

bottom x;
left *lp = &x;
base *bp = dynamic_cast<base *>(lp); // shared virtual base
right *rp = dynamic_cast<right *>(lp); // sibling subobject, or nullptr

这正是本章其余部分反对的代码：用运行时转换恢复一个本可以用组合表达的关系。如果你需要共享接口，优先用 没有数据的纯接口，或者组合加引用。如果你需要共享状态，用一个指针或引用成员显式表达共享，不要用虚基类。

虚继承不是通用的代码复用工具。它只适用于菱形确实是领域模型的一部分、并且一个共享基类子对象在语义上正确的 狭窄场景。它在布局、构造顺序和转换上都很昂贵，而且很容易写错。在新代码里，组合几乎总是更清晰。
