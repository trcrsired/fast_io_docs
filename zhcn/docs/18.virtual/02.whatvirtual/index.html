第18.2章 virtual 究竟是什么

English

1. 三件事，按顺序

virtual 函数不是魔法。它是三个机械事实：

  1. 多态类的每个对象都带一个隐藏指针（vptr）， 指向它所在类的函数指针表。所以这种对象不可能比一个指针更小， 而且至少按 alignof(void*) 对齐。
  2. 每个多态类在只读数据里有一张表（vtable）， 每个虚函数一个槽位，按声明顺序排列。它由编译器生成；你从来不用写，也改不了。
  3. 虚调用是：读 vptr、读槽位、跳转。两次相关加载而不是一次直接跳转， 而且目标地址在运行时才知道，所以不可能通过它内联。

机制就这些。本章其余内容 —— 膨胀、RTTI、__cxa_pure_virtual 符号、ABI —— 全都是由它推出来的。

2. 它的字节代价


struct drawable
{
	virtual ::std::string_view kind() const noexcept = 0;
	virtual ~drawable() noexcept = default;
};

struct point : drawable
{
	double x{}, y{};
	point(double px, double py) noexcept : x{px}, y{py} {}
	::std::string_view kind() const noexcept override { return "point"; }
};

struct square : drawable
{
	double side{};
	explicit square(double s) noexcept : side{s} {}
	::std::string_view kind() const noexcept override { return "square"; }
};


sizeof(drawable)=8 sizeof(point)=24 sizeof(square)=16 through base=point through object=square

算一下：point 是两个 double（16 字节）加 vptr（8）= 24。 square 是一个 double（8）加 vptr（8）= 16。 一个只有一个 double 的形状，因为一个函数是虚的，体积翻了一倍； 而一旦把它放到 ::std::unique_ptr 后面， 它又变成一个指针加分配器头部，再翻一次 （第18.1章）。

和本章后面的类型擦除版本对比：一个指针加一个表指针，16 字节， 能装下任何形状，载荷里没有 vptr，头部也不用分配。

3. 虚继承：菱形

基类列表里的 virtual 和函数上的 virtual 是两个不同的特性。它解决另一个问题： 多重继承可能把同一个公共基类的一份以上副本放进同一个对象。 

struct base
{
    int id{};
    virtual ~base() = default;
};

struct left : base
{
    int l{};
};

struct right : base
{
    int r{};
};

struct bottom : left, right
{
    int b{};
};

现在一个 bottom 对象包含两个 base 子对象：一个来自 left，一个来自 right。名字 id 有歧义，转换成 base& 也有歧义： 

bottom x;
// x.id = 1;            // error: ambiguous, which base?
// base &br = x;        // error: ambiguous base

left &l = x;
right &r = x;
base &bl = l;           // the base inside left
base &br = r;           // the base inside right

两个基类也有各自的状态。如果 base 里有一个 id，通过 bl 修改它不会通过 br 看到。对于真正的“是一个”菱形——一个共享的基类 子对象——把对 base 的继承声明为虚继承： 

struct left : virtual base
{
    int l{};
};

struct right : virtual base
{
    int r{};
};

struct bottom : left, right
{
    int b{};
};

现在 bottom 恰好有一个 base 子对象，由 left 和 right 两个分支共享。名字不再有歧义： 

bottom x;
x.id = 1;               // OK: one shared base
base &br = x;           // OK: one shared base
left &l = x;
base &bl = l;           // still refers to the same shared base

代价在布局。虚基类不能在每个完整对象里都放在固定偏移，因为通向它的路径取决于最派生类型。实现通常给类 加一个指针或偏移表（virtual base pointer，或 vbptr），访问虚基类成员变成间接访问。 标准不规定布局；sizeof、偏移和隐藏指针的数量都是 ABI 细节。不要在这些东西上构建线格式。

另一个锋利边缘是构造顺序。虚基类先于非虚基类构造，最派生类负责初始化虚基类。当中间类不是最派生对象时， 它对虚基类的初始化器会被忽略： 

struct base
{
    base() { std::print("base\n"); }
};

struct left : virtual base
{
    left() : base{} { std::print("left\n"); }
};

struct right : virtual base
{
    right() : base{} { std::print("right\n"); }
};

struct bottom : left, right
{
    bottom() { std::print("bottom\n"); }
};

bottom x; // base, left, right, bottom

析构按相反顺序：bottom、right、left、base。 如果你写了一个假设自己控制虚基类的构造函数，要分别把它当独立对象和更派生对象的基类来测试。同一个构造函数 在这两种情况下可能看到不同的基类初始化。

兄弟分支之间的交叉转换需要 RTTI。从 left* 到 right* 的 static_cast 不允许，因为编译器在没有完整对象时不知道偏移。dynamic_cast 可以找到共享基类或兄弟子对象，但它要求多态类型和一次运行时搜索： 

bottom x;
left *lp = &x;
base *bp = dynamic_cast<base *>(lp); // shared virtual base
right *rp = dynamic_cast<right *>(lp); // sibling subobject, or nullptr

这正是本章其余部分反对的代码：用运行时转换恢复一个本可以用组合表达的关系。如果你需要共享接口，优先用 没有数据的纯接口，或者组合加引用。如果你需要共享状态，用一个指针或引用成员显式表达共享，不要用虚基类。

虚继承不是通用的代码复用工具。它只适用于菱形确实是领域模型的一部分、并且一个共享基类子对象在语义上正确的 狭窄场景。它在布局、构造顺序和转换上都很昂贵，而且很容易写错。在新代码里，组合几乎总是更清晰。

4. 为什么 virtual 只有配合分配才“划算”

有一种不用堆的 virtual 用法：把派生对象按值放进容器，通过引用调用。


point p{1.0, 2.0};
square q{3.0};
drawable &d = p;                  // dispatch through a reference
::fast_io::io::println(d.kind());  // "point"

这是正确且不分配的，但注意它没有给你什么：类型集合在编译期就固定了， 每个变量只有一个静态类型，你没法把一个 point 和一个 square 放进同一个 ::fast_io::vector。 你一旦想要“任何可绘制对象的容器”，virtual 能给你的唯一东西就是基类指针， 而活得比作用域长的基类指针需要一个拥有者，C++ 的拥有者是 ::std::unique_ptr，而 ::std::unique_ptr 需要 new。

这就是那条链。virtual 本身并不是最贵的部分； virtual 加上异构才是，而异构恰恰是人们选 OOP 时想要的东西。 在链条上任何一环断开它 —— 用值代替指针、用类型擦除代替继承 —— 整套代价就消失了。

5. 诚实的代价模型

你要付什么 什么时候 本章里的实测
每个对象 8 字节 永远 sizeof(square) 从 8 变 16
每个类一张 vtable 永远 vtable for square，.rodata 里 48 字节
每个虚函数都被生成 即使从没被调用 12,448 字节死代码 （第18.4章）
每次分派一次间接调用 每次调用 不能内联、不能常量折叠、不能跨它向量化
每个类若干 RTTI 对象 永远 3 个类共 6 个 type-info 符号 （第18.5章）
__cxa_pure_virtual 及其运行时 任何一个纯虚函数 把 std::terminate、demangler、fwrite、 fputs、abort 都拉进来

只有一个分派点的程序，这些都不重要。有一千个类型搅在一个插件式层次里的程序， 这些就是 200 KB 二进制和 2 MB 二进制的差别， 是“瞬间启动”和“从磁盘加载自己的类型名”的差别。

6. 那什么时候可以接受 virtual

  • 当你在读遗留代码时。这是整个第18章最诚实的答案： virtual 是一个遗留特性。Qt、MFC、COM 和三十年的库都建立在它之上， 你必须能读。
  • 当库的 ABI 要求它时。如果平台递给你一个带虚函数的 struct（COM、某些驱动模型），实现它；不要用它做设计。
  • 当实现集合固定、封闭、且很少，而且对象都活在栈上时。 这时 virtual 就是一个语法更漂亮的 switch —— 而 ::std::variant 加 ::std::visit 能做同样的事， 而且根本没有 vptr。
  • 绝不在你正在设计的新抽象里用它。那种情况用函数指针表 （第18.6章）： 同样的分派机制，但有三个好处：你看得见它、你能把它实例化成常量、 而且它不会带来 RTTI、virtual ABI 规则和 __cxa_pure_virtual。

7. 经验法则

  • 写 virtual 之前，先把类型列表写下来。如果列表固定且已知， 你要的是标签、variant 或 switch，不是 vtable。
  • 如果列表是开放的（插件、用户提供的回调），你要的是一张你自己拥有的表， 这样你能给它定版本、把它放进 .rodata， 并让它成为你自己 ABI 的一部分，而不是 C++ 的 ABI。
  • 永远不要“以防万一”把类型做成多态的。那 8 个字节是这个错误里最便宜的部分。
  • 如果必须为分派而继承，让层次浅一些，所有东西都标注 （第18.3章）， 并且永远不要让基类指针逃进你自己的 API。
  • 只有当“一个共享基类子对象”就是领域语义时，才用虚继承。如果你说不清为什么这个基类必须共享， 用组合；虚基类是布局成本和构造顺序复杂度，不是复用工具。
