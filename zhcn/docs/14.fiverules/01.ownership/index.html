第14.1章: 所有权：为什么类需要析构函数

English

1. 描述符就是资源

::open 交给你一个 int。它不是你可以随便做算术的数字，而是内核所拥有的某个东西的句柄。三个性质使它成为资源：

  • 它必须被释放。内核为每个进程维护一张打开文件的表，它的大小是有限的。一个从不 ::close 的 int 会泄漏那张表的一个槽位。
  • 它在存活期间只有一个含义。这个数字在你关闭它之前一直有效；此后同一个数字就空出来了，程序中任何地方下一次 ::open 都可能再次发出它。
  • 它不是文件。两个描述符可以指名同一个文件，而同一个数字的两份拷贝指名同一个描述符。这两个事实在本章都很重要。

2. 一个裸 int 会怎样

一个普通变量完全不知道自己拥有什么。没有东西关闭它，于是一直活到进程结束： 


#include <fast_io.h>
#include <fast_io_dsal/string_view.h>

using namespace ::fast_io::io;

class my_posix_file
{
	int fd_{-1};

public:
	explicit my_posix_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws
	{
		::std::int_least32_t fd{::open(path.c_str(), flags, 0644)};
		if (fd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		fd_ = fd;
	}

	~my_posix_file() noexcept
	{
		if (fd_ != -1)
		{
			::close(fd_);
		}
	}

	[[nodiscard]] ::std::int_least32_t native_handle() const noexcept
	{
		return fd_;
	}
};

int main()
{
	// A bare int does not know it owns an operating system resource.
	::std::int_least32_t raw{::open("demo.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644)};
	println("bare int:  ", raw);

	// Nothing closes everything. The descriptor is leaked for the rest of the run.
	my_posix_file managed{"demo.txt", O_RDONLY};
	println("managed:   ", managed.native_handle());

	{
		my_posix_file scoped{"demo.txt", O_RDONLY};
		println("in scope:  ", scoped.native_handle());
	} // the destructor runs here
	my_posix_file after{"demo.txt", O_RDONLY};
	println("after:     ", after.native_handle());
}

输出：


bare int:  3
managed:   4
in scope:  5
after:     5

读一下这些数字。裸 int 拿走了描述符 3 并在整个运行期间占着它，所以之后每次 open 都得到一个新数字：4，然后是 5。块内那个受管理的文件拿到了 5，而当块结束时它把 5 还了回去 — 这就是为什么下一次 open 又收到 5 而不是 6。

这种复用正是析构函数运行过的证据。程序里没有任何地方显式调用 ::close；对象对自己的描述符负责，而这份责任被自动履行。

拥有意味着：任何能够到达该对象的人，无论以何种方式离开作用域，资源都会被释放。一次 return、一次 throw throws、一次 break、一次正常的落出 — 析构函数在所有这些情形中都会运行。而函数末尾显式的 ::close 在前三种情形里一次都不会运行。

3. 五个问题

拥有描述符的类必须说明在这五种情形下会发生什么。无处可逃：如果你什么都不说，编译器替你回答全部五个，而它对资源给出的答案都是错的。

问题写法错误的默认行为
对象消亡时，谁释放描述符？ ~my_posix_file() 没人：描述符泄漏
由已有对象构造新对象时发生什么？ my_posix_file(my_posix_file const &) 数字被复制：两个所有者，一个描述符
把另一个对象赋给已有对象时发生什么？ operator=(my_posix_file const &) 旧描述符泄漏，而新的那个被共享
用一个将亡对象构造新对象时，我们能直接接管吗？ my_posix_file(my_posix_file &&) 它会去复制，正确但浪费
已有对象从一个将亡对象接管时发生什么？ operator=(my_posix_file &&) 它会去复制，并且泄漏旧描述符

把五个都写出来，你就有了五法则。一个都不写、让编译器生成全部 — 这是零法则 — 是更好的结果，但只有当每个成员本身都是行为良好的值时才有可能。裸描述符不是（第14.11章会回到这一点）。

4. 我们要构建的东西

这个类刻意保持很小。它持有一个 int，其余全都是那五条规则： 


class my_posix_file
{
	int fd_{-1}; // -1 means "no descriptor"; it is the empty state

public:
	// 1. create: acquire a descriptor from a path
	explicit my_posix_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws;

	// 2. destroy: give the descriptor back                   -> Ch14.2
	~my_posix_file() noexcept;

	// 3. copy: a second descriptor for the same open file     -> Ch14.3
	my_posix_file(my_posix_file const &other) throws;

	// 4. copy-assign: replace what this object owns           -> Ch14.4
	my_posix_file &operator=(my_posix_file const &other) throws;

	// 5. move: take the descriptor and leave -1 behind        -> Ch14.5, Ch14.6
	my_posix_file(my_posix_file &&other) noexcept;
	my_posix_file &operator=(my_posix_file &&other) noexcept;

	// 6. swap: exchange two objects' descriptors              -> Ch14.7
	void swap(my_posix_file &other) noexcept;
};

哨兵值 -1 在真正干活：它是“我拥有一个文件”与“我什么都不拥有”之间的区别。没有它，就无法把一个被移出的对象留在一个析构函数能安全运行的状态。
