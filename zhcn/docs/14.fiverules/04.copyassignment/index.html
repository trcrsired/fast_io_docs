第14.4章: 复制赋值与那条临界线

English

1. 赋值不是构造

my_posix_file a{"demo.txt", O_RDONLY}; my_posix_file b{"other.txt", O_RDONLY}; 然后 a = b; 与 my_posix_file a{b}; 是完全不同的操作。

在赋值中，a 已经拥有一个描述符。无论这个函数怎么做，那个描述符最终必须被关闭 — 否则它就泄漏了 — 而 a 最终必须拥有 b 的副本。所以必须发生三件事，唯一真正的问题是顺序：

  • 获取新描述符（::dup，可能失败）；
  • 释放旧的（::close，在我们关心的意义上不会失败）；
  • 安装新的（一次 int 赋值，不会失败）。

2. 每个人最先写出的顺序

它读起来很自然：先把旧文件处理掉，再拿新的。 


	// WRONG
	my_posix_file &operator=(my_posix_file const &other) throws
	{
		if (fd_ != -1)
		{
			::close(fd_);          // the old file is gone
		}
		fd_ = ::dup(other.fd_);    // may fail -- and now there is nothing left
		if (fd_ == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		return *this;
	}

它有三个问题，值得分开讲。

  • 对象在新资源存在之前就被破坏了。如果 ::dup 失败，赋值失败并且刚才还开着的文件也没了。调用者拿到一个损坏的对象，而且没有回头路。
  • 自赋值会毁掉文件。a = a 关闭 a 的描述符，然后去复制 -1，以 EBADF 失败。完全合法的语句 a = a 让 a 被关闭并抛出异常。
  • 它看起来不是靠加一个检查就能修好的。加上 if (this == &other) return *this; 只是掩盖第二个问题，第一个问题丝毫未动。错的是顺序。

3. 临界线

把顺序反过来，一切就各就各位了。先在一个局部变量里做可能失败的工作，此时对象还未被触碰；然后，一旦再没有会失败的操作，就提交： 


	my_posix_file &operator=(my_posix_file const &other) throws
	{
		::std::int_least32_t newfd{::dup(other.fd_)};   // may fail, *this untouched
		if (newfd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		// ---- critical line ----
		reset(newfd);                                   // cannot fail, *this changes
		return *this;
	}
临界线是一个可能失败的函数内部的分界线：
— 在它之上，操作可能失败，而还没有任何东西被修改；
— 在它之下，操作不会失败，而它们才是修改对象的那些。
把它放在正确的位置，失败就只可能发生在还没有东西需要撤销的时候。这就是强异常安全保证，而临界线是获得它的方式。

数一数两侧的语句。线上：一次 ::dup 调用和一个检查，都可能失败，都不碰 *this。线下：一次 reset 调用，它是 noexcept，完成整个提交 — 关闭旧描述符、存入新的。不存在 *this 被赋值一半的状态，因为在旧值被触碰之后没有可失败的操作。

4. 自赋值不需要特殊处理

大多数教程会让你在赋值运算符开头写一个自赋值检查。用这个顺序你不需要：a = a 自己就能正常工作。

跟踪一下。::dup(a.fd_) 为同一个打开的文件产生第二个描述符；检查通过；然后 reset 关闭旧描述符并存入新的。a 现在拥有同一个文件的另一个描述符。没有丢失，没有泄漏，唯一可观察到的差别是一个新数字。

不要只因为大家都这么做就加那个检查。当操作无法容忍“读取自己即将销毁的东西”时才需要它 — 移动赋值正是这种情况（第14.6章），因为它先释放，没有副本可以退回。这里的复制赋值是先复制的，所以按构造就是自赋值安全的。

5. 两种顺序并排看

一个程序，两个类：正确的 my_posix_file 和一个先关闭的 naive_file。它演练了自赋值、一次失败的赋值，以及同样两种情况在朴素类上的表现。 


#include <fast_io.h>
#include <fast_io_dsal/string_view.h>

using namespace ::fast_io::io;

class my_posix_file
{
	int fd_{-1};

	void reset(::std::int_least32_t newfd = -1) noexcept
	{
		if (fd_ != -1)
		{
			::close(fd_);
		}
		fd_ = newfd;
	}

public:
	explicit my_posix_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws
	{
		::std::int_least32_t fd{::open(path.c_str(), flags, 0644)};
		if (fd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		fd_ = fd;
	}

	my_posix_file(my_posix_file const &other) throws : fd_{::dup(other.fd_)}
	{
		if (fd_ == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
	}

	my_posix_file &operator=(my_posix_file const &other) throws
	{
		::std::int_least32_t newfd{::dup(other.fd_)};
		if (newfd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		reset(newfd);
		return *this;
	}

	my_posix_file(my_posix_file &&other) noexcept : fd_{other.fd_}
	{
		other.fd_ = -1;
	}

	~my_posix_file() noexcept
	{
		reset();
	}

	[[nodiscard]] bool is_open() const noexcept
	{
		return fd_ != -1;
	}

	[[nodiscard]] ::std::int_least32_t native_handle() const noexcept
	{
		return fd_;
	}
};

class naive_file
{
	int fd_{-1};

public:
	explicit naive_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws
	{
		::std::int_least32_t fd{::open(path.c_str(), flags, 0644)};
		if (fd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		fd_ = fd;
	}

	~naive_file() noexcept
	{
		if (fd_ != -1)
		{
			::close(fd_);
		}
	}

	naive_file &operator=(naive_file const &other) throws
	{
		// WRONG: the old descriptor is gone before the new one exists.
		if (fd_ != -1)
		{
			::close(fd_);
		}
		fd_ = ::dup(other.fd_);
		if (fd_ == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		return *this;
	}

	[[nodiscard]] bool is_open() const noexcept
	{
		return fd_ != -1;
	}

	[[nodiscard]] ::std::int_least32_t native_handle() const noexcept
	{
		return fd_;
	}
};

int main()
{
	{ // make sure the example file exists
		::std::int_least32_t fd{::open("demo.txt", O_WRONLY | O_CREAT, 0644)};
		::close(fd);
	}

	my_posix_file a{"demo.txt", O_RDONLY};
	println("a before   = ", a.native_handle());
	a = a; // self-assignment
	println("a after a=a = ", a.native_handle(), ", is_open = ", a.is_open());

	my_posix_file moved_from{"demo.txt", O_RDONLY};
	my_posix_file b{::std::move(moved_from)};
	println("b = ", b.native_handle(), ", moved_from = ", moved_from.native_handle());
	try
	{
		a = moved_from;
	}
	catch throws (::std::error e)
	{
		print("a = moved_from failed: ", e, "\n");
	}
	println("a survived = ", a.native_handle(), ", is_open = ", a.is_open());

	naive_file n{"demo.txt", O_RDONLY};
	println("n before   = ", n.native_handle());
	try
	{
		n = n; // self-assignment, the naive way
	}
	catch throws (::std::error e)
	{
		print("n=n failed: ", e, "\n");
	}
	println("n after n=n = ", n.native_handle(), ", is_open = ", n.is_open());
}


a before   = 3
a after a=a = 4, is_open = 1
b = 3, moved_from = -1
a = moved_from failed: [posix](9)Bad file number
a survived = 4, is_open = 1
n before   = 5
n=n failed: [posix](9)Bad file number
n after n=n = -1, is_open = 0

四行承载了这个教训。

  • a after a=a = 4, is_open = 1 — 自赋值在没有检查的情况下成功了。数字变了，因为 ::dup 发出的是 4（旧的 3 在同一次调用中被关闭），而文件还是同一个文件。
  • a = moved_from failed: [posix](9)Bad file number — 赋值失败，因为右侧没有描述符（第14.10章）。
  • a survived = 4, is_open = 1 — 这正是重点：失败没有改变任何东西。a 仍然恰好持有它在语句之前持有的东西。
  • n after n=n = -1, is_open = 0 — 朴素的类关闭了自己的文件然后失败，留下一个有效但空的对象，原本那里有一个文件。没有任何东西损坏，但调用者丢掉了它从未要求放弃的资源。

6. 为什么返回类型是引用

operator= 返回 my_posix_file & — 对左操作对象的引用 — 实现就是 return *this;。这才让链式赋值成为可能： 


a = b = c;      // means a = (b = c), with b = c yielding b

(a = b).read_some(buf, n);   // the result of the assignment is a

改成按值返回就崩了：那个表达式会变成 a 的副本，于是链式赋值会复制一个描述符再把那个副本扔掉。永远返回 *this。

7. 什么时候不该有赋值

并非每个资源都能被替换。一把锁不能重新指向另一把锁；一个进行中的打开操作不能被从调用者脚下换掉。对这样的类型，正确答案是 = delete，与复制构造函数完全一样（第14.3章），而编译器会在调用点告诉你，而不是在凌晨三点。 


	my_lock &operator=(my_lock const &) = delete;
	my_lock &operator=(my_lock &amp;&amp;) = delete;

删除复制赋值并不意味着对象不能被复制 — 那是复制构造函数的事。它意味着对象不能被重新赋值，这是一个更弱的陈述。
