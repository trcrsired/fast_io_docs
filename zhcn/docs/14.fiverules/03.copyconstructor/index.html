第14.3章：拷贝构造：删除，或者深拷贝

English

1. 编译器的拷贝是浅的

每当用已有对象创建新对象，就会调用拷贝构造函数。如果你不声明，编译器会写一个逐成员拷贝。对拥有资源的类来说， 这个拷贝几乎总是错的。

上一页的 C++ Primer HasPtr 是最小的例子。它的析构函数释放 ps；编译器生成的拷贝 复制指针： 

HasPtr f(HasPtr hp)      // hp is a shallow copy
{
    HasPtr ret = hp;     // another shallow copy
    return ret;          // both destructors destroy ps
}

参数和局部对象共享同一个 std::string。函数返回时，同一个指针被析构两次，调用者的对象留下悬空。 bug 不是“析构函数存在”，bug 是拷贝被留给隐式版本。

只有两个合法答案：删除拷贝，或者写一个获取自己资源的拷贝。 没有第三个答案叫“交给编译器”。

警告：隐式拷贝不是资源的拷贝。 如果类拥有句柄，编译器生成的拷贝构造复制的是句柄。这就是有析构函数的类必须为两个拷贝操作声明 = delete、或者写真正实现的原因。“我有析构函数”是警告信号；“编译器会处理拷贝”是 bug。

2. 答案一：= delete

对资源所有者来说，这是默认。类拥有句柄；复制句柄会产生第二个所有者。删除两个拷贝操作： 

class my_posix_file
{
    int fd_{-1};

public:
    explicit my_posix_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws;
    ~my_posix_file() noexcept;

    my_posix_file(my_posix_file const &) = delete;
    my_posix_file &operator=(my_posix_file const &) = delete;

    my_posix_file(my_posix_file &&other) noexcept;
    my_posix_file &operator=(my_posix_file &&other) noexcept;
};

两个被删除的函数是声明。编译器在重载决议中使用它们，并用清晰的错误拒绝拷贝： 

error: use of deleted function 'my_posix_file::my_posix_file(const my_posix_file&)'
error: use of deleted function 'my_posix_file& my_posix_file::operator=(const my_posix_file&)'

这正是你要的。错误程序不能编译，错误指向拷贝。如果类型还应可移动，就声明移动操作。如果不该，也删除它们； 不可移动的所有者是完全合法的类型。

声明拷贝构造为 delete 也会阻止编译器生成移动构造。这就是上面的移动声明必须显式写出的原因。 删除拷贝又没有移动，类型既不能拷贝也不能移动；对不可移动所有者这是正确的，对应该可移动的类型则是意外。

3. 答案二：真正的深拷贝

如果拷贝有明确含义，就写一个创建新资源的拷贝构造。对 HasPtr 来说，就是一个新的 std::string： 

class HasPtr
{
public:
    HasPtr(std::string const &s = std::string())
        : ps{make_string(s)}, i{} {}

    HasPtr(HasPtr const &other)
        : ps{other.ps ? make_string(*other.ps) : nullptr},
          i{other.i}
    {
    }

    ~HasPtr() { destroy_string(ps); }

private:
    std::string *ps;
    int i;
};

新对象有自己的 ps。销毁一个对象不会影响另一个。空指针检查存在，是因为加入移动操作后， 移后 HasPtr 可能持有空指针；拷贝构造仍然应该安全。

深拷贝是真实操作，有真实成本：一次分配和一次字符串拷贝。这就是为什么对句柄来说删除是默认。 文件描述符可以用 ::dup 复制，但那是显式系统调用，为同一个打开文件创建第二个描述符； 它不是编译器逐成员拷贝做的事。如果你要这种语义，就显式写出来并记录共享关系。

4. 拷贝被删除时，std::move 做什么

::std::move 不移动任何东西。它转换成右值引用，让移动构造变得可匹配。如果没有声明移动构造， 重载决议回退到拷贝构造。如果拷贝构造被删除，回退目标就是被删除的函数，程序不能编译： 

my_posix_file a{"demo.txt", O_RDONLY};
my_posix_file b{::std::move(a)}; // error if no move constructor is declared

对 move-only 所有者来说，这是正确行为：转移所有权必须在类里显式实现，而不是意外拷贝。移动构造本身在 第14.5章。

5. 需要记住什么

  • 隐式拷贝是逐成员的；对句柄来说，就是第二个所有者。
  • 如果类有释放资源的析构函数，就声明拷贝。
  • 唯一所有权默认 = delete。
  • 只有当拷贝有定义明确的意义和成本时，才写深拷贝。
  • 同时删除拷贝构造和拷贝赋值；它们是一个决定。
  • 如果类型可移动，声明移动；如果不可移动，也删除移动。
