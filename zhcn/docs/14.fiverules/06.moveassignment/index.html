第14.6章: 移动赋值：先释放

English

1. 先释放，再夺取

移动赋值与复制赋值有相同的三个部分，而难易顺序相反：

  • 释放本对象拥有的东西（::close，不会失败）；
  • 安装源对象的描述符（一次 int 写入）；
  • 把源对象清空（一次 int 写入）。

这里没有任何会失败的东西，这正是整个运算符是 noexcept 的原因： 


	my_posix_file &operator=(my_posix_file &&other) noexcept
	{
		if (this == ::std::addressof(other)) [[unlikely]]
		{
			return *this;
		}
		reset(other.fd_);   // close ours, take theirs
		other.fd_ = -1;     // they own nothing now
		return *this;
	}

reset(other.fd_) 一次做两件事 — 关闭旧描述符并存入新的 — 而在这里这没问题，恰恰因为两步都不会失败。没有临界线要放，因为线上面什么都没有：整个函数都在线下面。

2. 自移动需要这个检查

移动赋值确实需要自检查，理由与复制赋值不需要它正好互为镜像。

复制赋值先复制，所以当 this == &other 时，在任何东西被关闭之前副本就已经存在了（第14.4章）。移动赋值先关闭，没有副本可以退回。对自身执行时的序列是：关闭描述符，然后把你刚关闭的那个描述符存进去，再把源对象清空 — 而源对象同时也就是目标。文件没了。 


	// WRONG: no self-check
	naive_file &operator=(naive_file &&other) noexcept
	{
		if (fd_ != -1)
		{
			::close(fd_);        // *this is now empty
		}
		fd_ = other.fd_;          // other IS *this: the closed number comes back
		other.fd_ = -1;
		return *this;
	}
复制赋值：不需要检查，因为先复制再销毁。
移动赋值：需要检查，因为先销毁再夺取。
这个不对称不是风格偏好。它直接来自哪个操作被允许先运行，而后者来自临界线。

3. 两者都验证过


#include <fast_io.h>
#include <fast_io_dsal/string_view.h>

using namespace ::fast_io::io;

class my_posix_file
{
	int fd_{-1};

	void reset(::std::int_least32_t newfd = -1) noexcept
	{
		if (fd_ != -1)
		{
			::close(fd_);
		}
		fd_ = newfd;
	}

public:
	explicit my_posix_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws
	{
		::std::int_least32_t fd{::open(path.c_str(), flags, 0644)};
		if (fd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		fd_ = fd;
	}

	my_posix_file(my_posix_file const &other) throws : fd_{::dup(other.fd_)}
	{
		if (fd_ == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
	}

	my_posix_file &operator=(my_posix_file const &other) throws
	{
		::std::int_least32_t newfd{::dup(other.fd_)};
		if (newfd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		reset(newfd);
		return *this;
	}

	my_posix_file(my_posix_file &&other) noexcept : fd_{other.fd_}
	{
		other.fd_ = -1;
	}

	my_posix_file &operator=(my_posix_file &&other) noexcept
	{
		if (this == ::std::addressof(other)) [[unlikely]]
		{
			return *this;
		}
		reset(other.fd_);
		other.fd_ = -1;
		return *this;
	}

	~my_posix_file() noexcept
	{
		reset();
	}

	[[nodiscard]] bool is_open() const noexcept
	{
		return fd_ != -1;
	}

	[[nodiscard]] ::std::int_least32_t native_handle() const noexcept
	{
		return fd_;
	}
};

class naive_file
{
	int fd_{-1};

public:
	explicit naive_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws
	{
		::std::int_least32_t fd{::open(path.c_str(), flags, 0644)};
		if (fd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		fd_ = fd;
	}

	naive_file(naive_file &&other) noexcept : fd_{other.fd_}
	{
		other.fd_ = -1;
	}

	naive_file &operator=(naive_file &&other) noexcept
	{
		// WRONG: no self-check. When other is *this, the file is closed and
		// the descriptor is then copied from itself as -1.
		if (fd_ != -1)
		{
			::close(fd_);
		}
		fd_ = other.fd_;
		other.fd_ = -1;
		return *this;
	}

	~naive_file() noexcept
	{
		if (fd_ != -1)
		{
			::close(fd_);
		}
	}

	[[nodiscard]] bool is_open() const noexcept
	{
		return fd_ != -1;
	}

	[[nodiscard]] ::std::int_least32_t native_handle() const noexcept
	{
		return fd_;
	}
};

int main()
{
	{ // make sure the example file exists
		::std::int_least32_t fd{::open("demo.txt", O_WRONLY | O_CREAT, 0644)};
		::close(fd);
	}

	my_posix_file a{"demo.txt", O_RDONLY};
	my_posix_file b{"demo.txt", O_RDONLY};
	println("a = ", a.native_handle(), ", b = ", b.native_handle());
	a = ::std::move(b);
	println("after a = move(b): a = ", a.native_handle(), ", b = ", b.native_handle(), ", b.is_open() = ", b.is_open());
	my_posix_file *alias{&a};
	a = ::std::move(*alias); // self-move through an alias
	println("after self-move:   a = ", a.native_handle(), ", a.is_open() = ", a.is_open());

	naive_file n{"demo.txt", O_RDONLY};
	println("n = ", n.native_handle());
	naive_file *nalias{&n};
	n = ::std::move(*nalias); // same, the naive way
	println("after self-move:   n = ", n.native_handle(), ", n.is_open() = ", n.is_open());
}


a = 3, b = 4
after a = move(b): a = 4, b = -1, b.is_open() = 0
after self-move:   a = 4, a.is_open() = 1
n = 3
after self-move:   n = -1, n.is_open() = 0
  • 移动成功了。描述符现在属于 a，b 为空，而 a 自己原先的描述符在进入时就被关闭了 — 输出的前两行就是没有泄漏的证明。
  • 自移动是空操作。检查在任何东西被触碰之前就运行了，所以 a 仍然拥有 4，文件完好。
  • 朴素的类把文件弄丢了。它关闭了自己的描述符，然后把刚关闭的那个数字存进去。对象没有损坏 — 那个数字现在恰好是 -1 — 但文件没了，而换一种顺序的函数体会留下一个悬空的 fd_。

程序里的自移动是故意通过指针 ::std::move(*alias) 进行的：真实代码中的自移动就是这么发生的 — 通过引用、下标，或者对容器的循环 — 而这正是编译器警告看不见的情形。直接写 a = ::std::move(a); 确实会得到 GCC 的警告： 


warning: moving 'a' of type 'my_posix_file' to itself [-Wself-move]

把那个警告当作你代码里的 bug，而不是类里的 bug。类仍然必须能承受它，因为编译器无法证明那些间接情形不存在。

4. 移动赋值与复制赋值对照

复制赋值 operator=(T const&) 移动赋值 operator=(T&&)
第一步 ::dup — 可能失败 ::close — 不会失败
自赋值检查 不需要：副本在关闭之前就取到了 必需：关闭发生在夺取之前
异常规格 throws noexcept
之后源对象拥有什么 和之前一样；它是被复制的，不是被夺取的 什么都不拥有：fd_ == -1
异常安全 强（副本失败时什么都不变） 不抛（没有任何东西会失败）

如果你不确定自己在写哪一个，就看这个函数对源对象做了什么。复制不动它；移动清空它。其余一切都由此而来。
