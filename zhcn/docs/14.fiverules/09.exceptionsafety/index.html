第14.9章: 异常安全：nothrow、strong、basic、none

English

1. 四个级别，不是一种感觉

“这个函数是异常安全的”本身什么也没说。调用者需要知道的是：失败之后对象的值还保住了多少。而答案恰好只有四种。

级别 失败之后调用者可以假定什么 声明为
nothrow 它根本不会失败。没有失败需要恢复。 noexcept
strong 它失败了，而对象完全和调用之前一样（提交或回滚）。 throws
basic 它失败了，对象依然有效 — 不变量成立、没有资源泄漏 — 但它的值可能变了，旧值已经没了。 throws
none 它失败了，对象可能处于破坏自身不变量的状态：不可用，或者更糟 — 可用但是错的。 throws

最后两行里真正起作用的是“有效”。有效意味着：每个成员函数仍然可以被调用，析构函数仍然做正确的事。我们的类把有效定义为 fd_ == -1，或者 fd_ 是一个仅由本对象拥有的打开描述符。

2. my_posix_file 的各个级别

最终类里每个成员及其级别。注意声明上的规格如何预示了级别：

成员 规格 级别 原因
~my_posix_file() noexcept nothrow 对有效描述符的一次 ::close，失败被忽略
my_posix_file(T&&) noexcept nothrow 两次 int 写入
operator=(T&&) noexcept nothrow 一次 ::close 加两次 int 写入
swap(T&) noexcept nothrow 三次 int 写入
reset()、is_open()、native_handle() noexcept nothrow 没有可能失败的系统调用
my_posix_file(path, flags) throws strong 抛出的构造函数意味着对象不存在；没有东西需要回滚
my_posix_file(T const&) throws strong ::dup 要么产生一个描述符，要么让源对象和新对象都不变
operator=(T const&) throws strong 先复制，然后越过临界线（第14.4章）
read_some()、write_some() throws 对对象是 strong，对文件是 basic 失败的 ::read/::write 不改变对象里的任何东西；但在文件本身，部分写入可能已经发生了

最后一行值得停一下。异常安全是这个对象的性质。一个写出到外部世界的函数，无论对自己的成员多么小心，都无法把外部世界回滚。

3. 四个级别，逐一验证


#include <fast_io.h>
#include <fast_io_dsal/string_view.h>

using namespace ::fast_io::io;

class my_posix_file
{
	int fd_{-1};

public:
	void reset(::std::int_least32_t newfd = -1) noexcept
	{
		if (fd_ != -1)
		{
			::close(fd_);
		}
		fd_ = newfd;
	}

	my_posix_file() noexcept = default;

	explicit my_posix_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws
	{
		::std::int_least32_t fd{::open(path.c_str(), flags, 0644)};
		if (fd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		fd_ = fd;
	}

	my_posix_file(my_posix_file const &other) throws : fd_{::dup(other.fd_)}
	{
		if (fd_ == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
	}

	my_posix_file &operator=(my_posix_file const &other) throws
	{
		::std::int_least32_t newfd{::dup(other.fd_)};
		if (newfd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		reset(newfd);
		return *this;
	}

	my_posix_file(my_posix_file &&other) noexcept : fd_{other.fd_}
	{
		other.fd_ = -1;
	}

	my_posix_file &operator=(my_posix_file &&other) noexcept
	{
		if (this == ::std::addressof(other)) [[unlikely]]
		{
			return *this;
		}
		reset(other.fd_);
		other.fd_ = -1;
		return *this;
	}

	~my_posix_file() noexcept
	{
		reset();
	}

	void swap(my_posix_file &other) noexcept
	{
		::std::int_least32_t const tmp{fd_};
		fd_ = other.fd_;
		other.fd_ = tmp;
	}

	[[nodiscard]] bool is_open() const noexcept
	{
		return fd_ != -1;
	}

	[[nodiscard]] ::std::int_least32_t native_handle() const noexcept
	{
		return fd_;
	}

	::std::size_t read_some(char *buf, ::std::size_t n) throws
	{
		auto ret{::read(fd_, buf, n)};
		if (ret == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		return static_cast<::std::size_t>(ret);
	}

	void reopen(::fast_io::cstring_view path, ::std::int_least32_t flags) throws
	{
		reset(); // BASIC: the old file is gone before the new one exists
		::std::int_least32_t fd{::open(path.c_str(), flags, 0644)};
		if (fd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		fd_ = fd;
	}

	::std::size_t write_some(char const *buf, ::std::size_t n) throws
	{
		auto ret{::write(fd_, buf, n)};
		if (ret == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		return static_cast<::std::size_t>(ret);
	}
};

inline void swap(my_posix_file &a, my_posix_file &b) noexcept
{
	a.swap(b);
}

// NO GUARANTEE: two resources, assigned one after the other.
class two_files
{
	my_posix_file reader_;
	my_posix_file writer_;

public:
	explicit two_files(::fast_io::cstring_view path) throws
		: reader_{path, O_RDONLY}, writer_{path, O_WRONLY}
	{}

	two_files(two_files const &other) throws : reader_{other.reader_}, writer_{other.writer_} {}
	two_files(two_files &&) noexcept = default;
	~two_files() = default;

	two_files &operator=(two_files const &other) throws
	{
		reader_ = other.reader_; // succeeds
		writer_ = other.writer_; // may fail, and then the pair is a mix
		return *this;
	}

	two_files &operator=(two_files &&other) noexcept = default;

	void close_writer() noexcept
	{
		writer_.reset();
	}

	[[nodiscard]] ::std::int_least32_t reader_handle() const noexcept
	{
		return reader_.native_handle();
	}

	[[nodiscard]] ::std::int_least32_t writer_handle() const noexcept
	{
		return writer_.native_handle();
	}
};

static_assert(noexcept(::std::declval<my_posix_file &>().swap(::std::declval<my_posix_file &>())));
static_assert(::std::is_nothrow_move_constructible_v<my_posix_file>);
static_assert(::std::is_nothrow_move_assignable_v<my_posix_file>);
static_assert(::std::is_nothrow_destructible_v<my_posix_file>);
static_assert(!::std::is_nothrow_copy_constructible_v<my_posix_file>);

int main()
{
	{ // make sure the example file exists
		::std::int_least32_t fd{::open("demo.txt", O_WRONLY | O_CREAT, 0644)};
		::close(fd);
	}

	// NOTHROW: the compiler proves these cannot fail.
	my_posix_file a{"demo.txt", O_RDONLY};
	my_posix_file b{"demo.txt", O_RDONLY};
	a.swap(b);
	println("nothrow: swap, move and destruction cannot fail");

	// STRONG: when the operation fails, nothing changed.
	my_posix_file source{"demo.txt", O_RDONLY};
	my_posix_file stolen{::std::move(source)};
	try
	{
		a = source; // source has no descriptor left to duplicate
	}
	catch throws (::std::error e)
	{
		print("strong: ", e, ", a is still ", a.native_handle(), "\n");
	}

	// BASIC: the object is still usable, but its old value is gone.
	my_posix_file basic{"demo.txt", O_RDONLY};
	try
	{
		basic.reopen("/nonexistent/file", O_RDONLY);
	}
	catch throws (::std::error e)
	{
		print("basic:  ", e, ", is_open = ", basic.is_open(), "\n");
	}

	// NO GUARANTEE: the pair no longer belongs to one file.
	two_files dst{"demo.txt"};
	two_files src{"demo.txt"};
	src.close_writer();
	println("none:   before: dst reader = ", dst.reader_handle(), ", writer = ", dst.writer_handle());
	try
	{
		dst = src;
	}
	catch throws (::std::error e)
	{
		print("none:   ", e, "\n");
	}
	println("none:   after:  dst reader = ", dst.reader_handle(), ", writer = ", dst.writer_handle());
}


nothrow: swap, move and destruction cannot fail
strong: [posix](9)Bad file number, a is still 4
basic:  [posix](2)No such file or directory, is_open = 0
none:   before: dst reader = 6, writer = 7
none:   [posix](9)Bad file number
none:   after:  dst reader = 9, writer = 7

逐行看：

  • nothrow。swap、各个移动以及析构函数是在编译期断言的，不是在运行期测试的。没有什么可观察，因为什么都不会发生。
  • strong。赋值以 [posix](9)Bad file number 失败，而 a 仍然是 4 — 语句之前它持有的同一个描述符。临界线完成了它的工作。
  • basic。reopen 先关闭旧文件，再打开新文件；打开以 [posix](2)No such file or directory 失败，而对象现在是关闭的。它完全有效 — 你可以销毁它、给它赋值、问 is_open() — 但它原本拥有的文件没了。这是“承担不起先打开新的再关闭旧的”这一做法的诚实代价。
  • none。那对句柄是逐成员赋值的。读者被替换了（6 变成 9，源对象读者的一个副本），写者没有（7 保持不变），然后赋值抛出了。两个成员各自都有效；这一对无效，而类外面没有任何代码能看出来或修好它。

4. 如何获得强保证

有两个配方，而两者都是伪装的临界线。

  • 先把所有可能失败的工作做进局部变量。然后用不会失败的操作执行改动。这就是 my_posix_file 的复制赋值。
  • 构造一个完整的临时对象，然后把它交换进来。这就是复制并交换（第14.8章），它能扩展到任意多个成员。

还有两种失去它的方式，也值得点名：

  • 先修改，再做可能失败的事。就是上面的 reopen；级别立刻掉到 basic。
  • 先修改部分成员，然后在其余成员上失败。就是那个朴素的双成员赋值；级别掉到 none。
强保证并不总是付得起。回滚意味着让旧值活下去，而对一个 10 GB 的缓冲区来说，那就是整个缓冲区。在对象很小、不变量又重要的地方选强保证（文件句柄、socket、锁、小容器）；在复制根本不可能的地方选 basic；而永远不要不经意地选 none。

5. 赫布异常让 noexcept 成为一份证明

在传统 C++ 中，noexcept 是一个编译器照单全收的承诺，并在运行期用 std::terminate 来惩罚它。一个 noexcept 函数可以调用任何它喜欢的东西，直到它抛出的那一夜才有人发现。

在赫布异常下，承诺在它被许下的地方就被检查。一个 noexcept 函数根本不能调用 throws 函数，除非它在自己的函数体里处理失败： 


error: call to a 'throws' or 'return_failure{E}' function must be handled by an enclosing
       'try { } catch throws', or the calling function needs a herbceptions specification
       so the error can propagate

由此有三点后果，而它们正是本章能够做到精确的原因：

  • “这个函数是 nothrow”是关于代码的事实，不是一句注释。如果你能用 noexcept 编译它，它就不会失败。
  • 临界线被强制执行。线下面的一切都必须可 noexcept 调用，编译器拒绝其他任何东西 — 提交的序列是被机械检查的。
  • 级别在声明处可见。头文件里的 noexcept 告诉读者 nothrow；throws 告诉读者“strong 或 basic，文档里说明是哪个”。这就是本教程每个成员函数都带这两者之一的原因（第6.16章）。
析构函数是 noexcept，所以析构函数恰好只有 nothrow 保证。任何可能失败、而你又想知道的事情，都必须是调用者能用 try { } catch throws 包裹的具名成员函数。这一条规则解释了真实的文件、socket 和数据库 API 的大部分形态 — 包括 fast_io 的：它的 close() 会报告，而它的析构函数不会。
