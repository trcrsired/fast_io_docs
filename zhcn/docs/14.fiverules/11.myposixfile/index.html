第14.11章: 完整的类，以及 fast_io 的 posix_file

English

1. 完整的类

前面九个子章的全部内容，汇成一块。在顶部加上 #include <fast_io.h> 与 #include <fast_io_dsal/string_view.h>，它就是一个完整的头文件，里面没有别的代码：一个 int、六个特殊成员、swap，以及使它成为一个文件的两种操作。 


class my_posix_file
{
	int fd_{-1};

public:
	void reset(::std::int_least32_t newfd = -1) noexcept
	{
		if (fd_ != -1)
		{
			::close(fd_);
		}
		fd_ = newfd;
	}

	my_posix_file() noexcept = default;

	explicit my_posix_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws
	{
		::std::int_least32_t fd{::open(path.c_str(), flags, 0644)};
		if (fd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		fd_ = fd;
	}

	my_posix_file(my_posix_file const &other) throws : fd_{::dup(other.fd_)}
	{
		if (fd_ == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
	}

	my_posix_file &operator=(my_posix_file const &other) throws
	{
		::std::int_least32_t newfd{::dup(other.fd_)};
		if (newfd == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		// ---- critical line ----
		reset(newfd);
		return *this;
	}

	my_posix_file(my_posix_file &&other) noexcept : fd_{other.fd_}
	{
		other.fd_ = -1;
	}

	my_posix_file &operator=(my_posix_file &&other) noexcept
	{
		if (this == ::std::addressof(other)) [[unlikely]]
		{
			return *this;
		}
		reset(other.fd_);
		other.fd_ = -1;
		return *this;
	}

	~my_posix_file() noexcept
	{
		reset();
	}

	void swap(my_posix_file &other) noexcept
	{
		::std::int_least32_t const tmp{fd_};
		fd_ = other.fd_;
		other.fd_ = tmp;
	}

	[[nodiscard]] bool is_open() const noexcept
	{
		return fd_ != -1;
	}

	[[nodiscard]] ::std::int_least32_t native_handle() const noexcept
	{
		return fd_;
	}

	::std::size_t read_some(char *buf, ::std::size_t n) throws
	{
		auto ret{::read(fd_, buf, n)};
		if (ret == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		return static_cast<::std::size_t>(ret);
	}

	::std::size_t write_some(char const *buf, ::std::size_t n) throws
	{
		auto ret{::write(fd_, buf, n)};
		if (ret == -1) [[unlikely]]
		{
			throw throws static_cast<::std::errc>(errno);
		}
		return static_cast<::std::size_t>(ret);
	}
};

inline void swap(my_posix_file &a, my_posix_file &b) noexcept
{
	a.swap(b);
}

从上往下读，你就能看到整章：reset 是唯一的 ::close（第14.2章）；复制构造函数做复制（第14.3章）；复制赋值有那条临界线（第14.4章）；移动构造函数清空它的源（第14.5章）；移动赋值有自检查（第14.6章）；swap 是三次写入（第14.7章）。凡是只搬一个数字的都是 noexcept；凡是调用内核的都是 throws — 即第14.9章的分类，在声明处就看得见。

inline void swap(my_posix_file &a, my_posix_file &b) noexcept
{
	a.swap(b);
}

int main()
{
	{
		my_posix_file out{"demo.txt", O_WRONLY | O_CREAT | O_TRUNC};
		out.write_some("herbceptions\n", 13);
	}

	my_posix_file in{"demo.txt", O_RDONLY};
	char buf[32]{};
	auto n = in.read_some(buf, sizeof(buf));
	print("read back: ", ::fast_io::mnp::os_c_str_with_known_size(buf, n));

	my_posix_file copy{in};
	println("in = ", in.native_handle(), ", copy = ", copy.native_handle());

	::fast_io::vector<my_posix_file> files;
	files.push_back(::std::move(copy));
	println("the vector holds ", files.size(), " file, fd = ", files.front().native_handle());

	swap(in, files.front());
	println("after swap: in = ", in.native_handle(), ", files.front() = ", files.front().native_handle());
}


read back: herbceptions
in = 3, copy = 4
the vector holds 1 file, fd = 4
after swap: in = 4, files.front() = 3

这个类与本教程的其他一切都能配合：它能进 ::fast_io::vector，因为它的移动是 noexcept；它能挺过容器的重新分配，因为移动赋值释放了它该释放的东西；而 swap 在一次系统调用都没有的情况下，把所有权在 vector 和一个局部对象之间搬移。

4. fast_io 的 posix_file 多了什么

真正的那个位于 include/fast_io_hosted/platforms/posix/file.h，它是 basic_posix_family_file，也就是同一个类，加上库需要而教程不需要的那些部分：

  • 它是模板。family 与 ch_type 意味着同一份代码服务 posix_file、u8posix_file、wposix_file 以及 Win32/NT 家族。那是第15章的活。
  • 它是 io_observer 基类加一个文件。观察者知道如何读、写、散布、聚集和查询描述符；文件在其上增加所有权。fast_io 的整个设计就是“句柄”与“句柄的拥有者”之间的这种切分。
  • 路径是模板参数。::fast_io::constructible_to_os_c_str 接受 cstring_view、::fast_io::string 或普通字面量，并转换成平台想要的形式。我们只接受 ::fast_io::cstring_view，别的都不接受，好让示例保持可读。
  • 它有一个会报告的 close()。::close 可能失败，而调用者可能在意；所以这个类在 noexcept 析构函数旁边提供了 void close() throws — 就是第14.2章讲的那种切分。
  • 它懂 Windows。同一个文件还带着 Cygwin、Wine、NT 和 Win32 的构造函数，它的长度大部分来自这些。我们的精简版一点都没有。
  • 它删除了危险的转换。从 io_observer 构造文件会把一个句柄变成两个所有者，所以那个构造函数是 = delete，正如第14.3章所建议的。

这些附加物没有一条改变了这些页面上的任何规则。这正是用一个五十行的类来学它们的意义：五千行的类的第五条规则还是同一条规则。

5. 零法则

在你写出其中任何一个之前，先检查你是否必须写。如果你类的每个成员本身已经是行为良好的值 — 一个 int、一个 ::fast_io::string、一个 ::fast_io::vector — 那么编译器生成的复制、移动和析构全都正确，你一个都不该写： 


class config
{
	::fast_io::string name_;
	::fast_io::vector<::fast_io::string> keys_;
	// nothing else: the five special members are generated, and they are right
};

这就是第13章从未提到这些的原因：一个由数字和字符串构成的类一个都不需要。五法则是拥有裸资源的代价，而支付它最便宜的方式就是不去拥有 — 把那个 int 放进一个已经实现了五法则的类里，让组合来干活。

6. 检查清单

  • 这个类拥有资源吗？如果不拥有，五者一个都不要写。
  • 有表示“不拥有任何东西”的哨兵值，并且在成员处初始化了吗？
  • 是否恰好只有一个地方释放它，而那个地方是 noexcept 吗？
  • 析构函数处理空状态时，是否不调用任何系统函数？
  • 复制构造函数是否产生新资源，或者复制是否已被删除？
  • 复制赋值是否在临界线之前完成了所有可能失败的工作？
  • 移动赋值是否清空了它的源？
  • 移动赋值是否检查了自赋值？
  • swap 是 noexcept 吗？是否也有一个自由 swap？
  • 你能说出每个成员函数的异常安全级别吗？

7. 错误，以及它们长什么样

错误症状
没有析构函数 描述符不断积累，直到 ::open 以 EMFILE 失败

8. 接下来是什么

这个类是为一种字符类型和一个平台家族写的。下一章把它变成模板，让同一份代码服务 char、char8_t、wchar_t 以及 Windows 各后端 — 而你会认出其中的每一行，因为模板不改变五法则，它们只是为更多类型重复它。

另一个方向是第16章：<<、== 之类的运算符可以为一个像这样的类编写，而它们恰好提出你刚刚回答过的那些关于复制、移动和失败的问题。
