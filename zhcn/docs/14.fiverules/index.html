第14章: 五法则：复制、移动、交换

English

1. 为什么需要这一章

第13章里的每个类拥有的都是数字。复制一个显然无害：point b{a} 得到两个点，没有任何共享。account 拥有的是一笔余额，复制它同样无害。

一旦类拥有由操作系统发放的东西 — 文件描述符、socket、锁、一块内存 — 这份安心就结束了。两个对象拥有同一个描述符是一个等着发生的 bug，而编译器的默认行为制造的恰好就是这个 bug：它复制那个数字，而不是复制资源。

这样的类必须回答五个问题，本章就是这五个答案。

2. 什么是资源

资源是任何满足下列条件的东西：

  • 使用之前必须获取，使用之后必须释放，
  • 只能被获取有限次，
  • 由一个句柄标识，你传递句柄而不是传递那个东西本身。

文件描述符是最小的有用例子。::open 返回一个 int；::close 把它还回去；进程能拥有的数量是有限的；而这个 int 是句柄，不是文件。复制句柄不会复制文件 — 它给同一个东西起了第二个名字，而一个资源有两个所有者，正是本章要解决的问题。

3. 五个特殊成员函数

你不写它们时，编译器替你写。你写了其中一个时，其余的含义会改变。它们是：

成员 何时被调用 子章
析构函数 ~T() 对象离开作用域，或被删除 第14.2章
复制构造函数 T(T const&) 由一个已有对象构造新对象 第14.3章
复制赋值 operator=(T const&) 把一个已有对象赋予另一个对象的值 第14.4章
移动构造函数 T(T&&) 由一个即将消亡的对象构造新对象 第14.5章
移动赋值 operator=(T&&) 一个已有对象从一个即将消亡的对象接管资源 第14.6章
swap 你按名字调用它 第14.7章

其中五个是编译器会替你生成的特殊成员；swap 不是 — 除非你写出调用，否则没人会调用它。它仍然属于这里，因为它是唯一一个能让复制赋值变得安全的操作（第14.8章），也因为 ::std::swap 会退化成三次移动，而只有你的移动是 noexcept 时它才既快又安全。

4. 贯穿全章的示例：my_posix_file

从这一页开始的每一页都使用同一个贯穿示例：一个拥有 POSIX 文件描述符的类。它是 fast_io 自己在 basic_posix_file 里所做工作的简化版本，只保留五法则需要的东西，从而让有意思的代码永远不超过十五行。 


class my_posix_file
{
	int fd_{-1};

public:
	my_posix_file() noexcept = default;
	explicit my_posix_file(::fast_io::cstring_view path, ::std::int_least32_t flags) throws;
	my_posix_file(my_posix_file const &other) throws;
	my_posix_file &operator=(my_posix_file const &other) throws;
	my_posix_file(my_posix_file &&other) noexcept;
	my_posix_file &operator=(my_posix_file &&other) noexcept;
	~my_posix_file() noexcept;
	void swap(my_posix_file &other) noexcept;

	[[nodiscard]] bool is_open() const noexcept;
	[[nodiscard]] ::std::int_least32_t native_handle() const noexcept;
	::std::size_t read_some(char *buf, ::std::size_t n) throws;
	::std::size_t write_some(char const *buf, ::std::size_t n) throws;
};

路径是 ::fast_io::cstring_view，标志是普通的 POSIX int 标志（O_RDONLY、O_WRONLY | O_CREAT 等），函数体直接调用 ::open、::dup 和 ::close。没有任何东西藏在 fast_io 的辅助设施后面，所以本章陈述的每一条规则都能对着页面上的代码核对。

失败用本教程唯一的报告方式报告（第3.16章）： 


if (fd == -1) [[unlikely]]
{
	throw throws static_cast<::std::errc>(errno);
}

在 POSIX 系统上标准的 ::std::errc 取值就是 errno 的取值，所以强制转换精确保留了错误；处理者会看到 [posix](2)No such file or directory 之类的内容。

5. 为本章付账的两个想法

规则本身只是记账。有两个想法让它们值得学，也正是本章存在的理由。

那条临界线

在一个可能失败的函数内部，存在一条线 — 有时很明显，有时只是一个语句 — 使得

  • 在它之上：允许失败，而还没有任何东西被修改；
  • 在它之下：不允许失败，修改就在那里发生。

把每个可能失败的步骤放到线之上、每个改动放到线之下，这个操作要么完整发生，要么完全不发生。这就是强异常安全保证，也正是第14.4章真正要讲的东西。

异常安全的四个级别

nothrow、strong、basic、none — 你写的每个函数必然恰好属于其中之一，无论你是否想过这个问题。第14.9章为它们命名，对 my_posix_file 的每个成员分类，并说明赫布异常如何把第一级从一句承诺变成编译器能证明的东西。

6. 本章使用的约定

  • 私有数据成员以下划线结尾：fd_。
  • 每个成员函数要么是 noexcept，要么是 throws — 本教程中不存在第三个选项（第6.16章）。它是哪一个，会在你读函数体之前就告诉你异常安全级别。
  • 整数用 ::std::int_least32_t、::std::int_least64_t 或 ::std::size_t，绝不用裸 int。唯一的例外是 int main()，以及 POSIX API 自身的 int 参数和返回值，它们就按 int 展示。
  • 失败用赫布异常：throw throws ... 与 catch throws (::std::error e)。
  • 这些页面上的每个完整程序都用 -std=c++26 -fherbceptions -lherbceptions 编译并运行过；显示的输出就是它实际打印的内容。
