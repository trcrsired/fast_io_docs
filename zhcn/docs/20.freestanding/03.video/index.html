第20.3章：观看：Freestanding C++ 的过去、现在与未来

English

问题背后的历史

这一章讲的是独立 C++ 做不到什么，以及为什么。这场演讲讲的是历史：独立子集最初是怎么被规定的， 为什么它的头文件清单在语言不断增长的同时二十年没动，C++23 的工作如何终于交付了一份可用的清单， 以及剩下的窟窿是怎么来的。演讲者是 Ben Saks，来自 CppCon 2019，是关于这个主题最好的一小时讲述。

演讲

按演讲展开的顺序，值得注意这些点：

  • "freestanding" 原本想表达什么。本意是一门能用于无操作系统程序的 C++； 标准交付的却是一份暗示了操作系统的头文件清单。
  • 为什么语言没有缩小。语法保留了异常、RTTI 和 new， 即使运行时根本不存在（20.1）。
  • 缺什么，逐项打分。演讲列举了那些头文件，并解释哪些能做成独立的、哪些不能。
  • 为什么容器永远进不去。vector 的接口就是一个堆加一个异常； 改措辞救不了这一点（20.1）。

看完之后

带着演讲留下的问题回来，因为前面两页用 2019 年的演讲无法假定的机制回答了它们：

  • 20.1 — 一次遗留 throw 究竟向链接器要求什么，以及为什么你提供不了。
  • 20.2 — 在独立环境里确实能用的错误处理： 一个数据符号、没有 unwinder，以及 [domain](code) 而不是一张消息表。
  • 20.2 — 一个把分配器和设备做成类型参数的程序， 这才是"独立库"该有的样子，而它几乎从来不是。
