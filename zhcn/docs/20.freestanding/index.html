第20章：独立

English

为什么有这一章

前面的每一章都假设你下面有一个操作系统：malloc 后面有一个堆，print 后面有一个控制台，还有一个 unwinder、一个加载器和一个 C 库。这一章把这些全部拿走，然后问：还剩什么。

答案不是"更小的 C++"。它是被拿走了操作系统服务的 C++。真正有意思的问题是：你被教导去依赖的那些东西里， 哪些其实是语言，哪些其实是操作系统。

这一章刻意写得很短：三页，讲问题、讲库、讲一场演讲。

三页内容

  1. 20.1 问题：C++ 不是为独立实现设计的
  2. 20.2 fast_io 的独立实现能力
  3. 20.3 观看：独立 C++ 的过去、现在与未来

一句话版本

C++ 是作为宿主语言设计的，而标准的模型至今仍是宿主优先：独立实现只是头文件清单更短的宿主实现， 不是一个有自己需求的目标。因此那些需要堆、unwinder、RTTI、线程指针或启动代码的特性仍然留在语法里， 只是在裸机上链接失败。C++26 的 DIS 投票于 2026 年 10 月 23 日因契约（contracts）未通过， 所以它带来的独立实现新增项仍然在一份未批准的草案里。

因此一个独立 C++ 程序要做四件事：禁止遗留异常和 RTTI，自己提供启动代码和堆，永远不用全局 operator new，并且使用一个把分配来源和 I/O 设备做成类型参数的库。这就是 fast_io 的用途，也是本书所有内容都以它为基础的原因。

要点

  • freestanding 去掉的是操作系统运行时，不是语言。
  • 只有 -ffreestanding 不够；库本身也必须支持。
  • 目标没有堆、控制台或 unwinder 时，fast_io 仍然可用。
  • hosted 假设必须在程序边界处显式写出来。
