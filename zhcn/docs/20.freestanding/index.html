第20章：Freestanding

English

为什么有这一章

前面的每一章都假设你下面有一个操作系统：malloc 后面有一个堆，print 后面有一个控制台，还有一个 unwinder、一个加载器和一个 C 库。这一章把这些全部拿走，然后问：还剩什么。

答案不是"更小的 C++"。它是被拿走了操作系统服务的 C++。真正有意思的问题是：你被教导去依赖的那些东西里， 哪些其实是语言，哪些其实是操作系统。

这一章刻意写得很短：三页，讲问题、讲库、讲一场演讲。

三页内容

  1. 20.1 问题：C++ 不是为独立实现设计的 — 以 Linus Torvalds 2004 年那封邮件开场，讲标准对独立实现的定义、为什么 -ffreestanding 不等于一套独立工具链，以及异常、RTTI、new、 thread_local、启动代码和浮点各自要向运行时要什么。
  2. 20.2 fast_io 的独立实现能力 — 头文件分层、把分配器放进容器类型、赫布异常、把设备做成类型参数，以及没有宿主运行时的检查清单。
  3. 20.3 观看：Freestanding C++ 的过去、现在与未来 — Ben Saks，CppCon 2019，以及该听什么。

一句话版本

C++ 是作为宿主语言设计的。它的独立模式只是一个更短的头文件清单，而不是一门更小的语言，所以那些需要堆、unwinder、 RTTI、线程指针或启动代码的特性仍然留在语法里，只是在裸机上链接失败。

因此一个独立 C++ 程序要做四件事：禁止遗留异常和 RTTI，自己提供启动代码和堆，永远不用全局 operator new，并且使用一个把分配来源和 I/O 设备做成类型参数的库。这就是 fast_io 的用途，也是本书所有内容都以它为基础的原因。
