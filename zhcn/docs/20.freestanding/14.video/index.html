第20.14章：观看：Freestanding C++ —— 过去、现在与未来

English

看这个，理解我们是怎么走到今天的

本章讲的是独立 C++ 不能做什么以及为什么。这个演讲讲的是历史：独立子集是如何被规定的、为什么它在语言不断长大的二十年里一直没变、C++23 的工作如何终于交付了一份可用的清单，以及剩下的那些窟窿是从哪里来的。讲者是 Ben Saks，CppCon 2019，这是关于这个主题最好的一小时。

演讲

按演讲提出的顺序，值得留意的几点：

  • "独立"本来应该是什么意思。本意是一个你可以用来写没有 OS 的程序的 C++；标准交付的，是一份暗示了 OS 存在的头文件清单。
  • std::addressof 那一类窟窿。那些运行期什么都不需要、却仍然不在清单上的特性（20.12）。
  • 缺什么，逐项打分。演讲列举了那些头文件并解释了哪些能做成独立的、哪些不能，那就是 20.6 里的那张表。
  • 为什么容器永远进不去。vector 的接口就是一个堆加一个异常；改措辞救不了这一点（20.7）。

看完之后

带着演讲留下的问题回来，因为本章用 2019 年那场演讲无法做出的测量来回答它们：

  • 20.3 —— 一次遗留 throw 究竟向链接器要求什么，以及为什么你提供不了。
  • 20.10 —— 在独立环境里确实能用的错误处理：一个符号、没有 unwinder，以及 [domain](code) 而不是一张消息表。
  • 20.13 —— 一个未定义符号为零的程序，这才是"独立库"该有的样子，而它几乎从来不是。
