第7.4章: if consteval

English

概述

if consteval 检查当前这次函数调用是否正在常量表达式 上下文中求值。它允许函数在编译期执行与运行时执行 表现出不同的行为。

与依赖常量表达式值的 if constexpr 不同， if consteval 取决于函数如何被求值。

1. 基础示例

当函数在编译期求值时，会选中 if consteval 分支。在运行时求值时，则选中 else 分支。 


#include <fast_io.h>

constexpr int compute(int x) throws
{
    using namespace ::fast_io::iomnp;

    if consteval
    {
        print("computed at compile time\n");
        return x * 2;
    }
    else
    {
        print("computed at runtime\n");
        return x + 2;
    }
}

编译器根据求值上下文选择分支。

2. 强制编译期求值

constexpr 变量会强制其初始化器在编译期求值。 这意味着会选中 if consteval 分支。 


constexpr int a = compute(10);  // compile-time evaluation
int b = compute(10);            // runtime evaluation

第一次调用会打印“computed at compile time”，第二次会打印 “computed at runtime”。

3. 为什么这很有用

当函数必须做到以下事情时，if consteval 很有用：

  • 在编译期执行不同的逻辑
  • 在常量求值期间避开仅限运行时的操作
  • 为编译期用法提供更好的诊断

例如，当函数在编译期求值时，你可能想禁止某些操作。 


#include <fast_io.h>

constexpr int safe_divide(int a, int b) throws
{
    using namespace ::fast_io::iomnp;

    if consteval
    {
        if(b == 0)
            print("error: division by zero in constant expression\n");
    }

    return a / b;
}

这允许进行编译期检查，而不会影响运行时行为。

4. 否定形式：if !consteval

同一个判断也可以反过来写。if !consteval 就是两个分支对调的 if consteval，它并没有多出任何能力 — 它存在的意义是让你 把平常的那条路径写在前面：当几乎所有调用都是运行期调用、常量求值只是例外时， 这种写法更贴合事实： 


#include <fast_io.h>

constexpr ::std::uint_least64_t fib(int n) noexcept
{
    if !consteval
    {
        // Ordinary calls land here: iterate. O(n) time, O(1) stack.
        ::std::uint_least64_t a{}, b{1};
        for (int i{}; i != n; ++i)
        {
            ::std::uint_least64_t const next{a + b};
            a = b;
            b = next;
        }
        return a;
    }
    else
    {
        // Constant evaluation: the textbook recursion, folded by the compiler.
        return n < 2 ? n : fib(n - 1) + fib(n - 2);
    }
}

int main()
{
    using namespace ::fast_io::iomnp;

    try
    {
        constexpr ::std::uint_least64_t folded{fib(20)};   // constant-evaluated
        ::std::uint_least64_t const looped{fib(20)};       // runtime, from the loop
        println("folded = ", folded, ", looped = ", looped);
    }
    catch throws (::std::error e)
    {
        ::fast_io::perrln(e);
        return 1;
    }
    return 0;
}

两次调用都得到 6765，走的是两条不同的代码路径，而且任何一条路径都不会为另一种上下文生成。

else 是可以省掉的，但那样一来，只要函数正在被常量求值， 执行就会继续越过这个块，因为这个块被整个跳过了： 


constexpr int scale(int x) noexcept
{
    if !consteval
    {
        return x + 2;     // runtime only
    }
    return x * 2;         // reached only during constant evaluation
}

所以否定形式里的运行期分支必须 return 或 throw： 否则代码会掉出去，在两种上下文里都执行。当两条路径不是一眼就能看清时， 请写显式的 else。

运行期调用必须放在哪里。不要用命名空间作用域的变量去演示运行期路径。 恰好是常量表达式的初始化器会在静态初始化期间就被应用，所以这不是一次运行期求值， if !consteval 块会被跳过： 

int a{scale(10)};   // constant-initialized: 20, NOT 12

int main()
{
    int b{scale(10)};   // automatic variable: 12, the runtime branch
}
把运行期调用留在函数内部，或者用 constinit （第7.5章） 明说出你要的就是编译期初始化。

5. 与 if constexpr 的区别

if constexpr 取决于一个常量表达式的值： 


if constexpr(flag) { ... }

if consteval 取决于求值上下文： 


if consteval { ... }

它们解决不同的问题：

  • if constexpr 根据常量值选择代码。
  • if consteval 根据函数是否正在编译期求值来选择代码。

要点

  • if consteval 检查当前这次函数调用是否在编译期求值。
  • 它允许函数在编译期与运行时上下文中表现不同。
  • constexpr 变量强制编译期求值。
  • 适用于诊断、限制，以及依上下文而异的行为。
  • if !consteval 是同样的判断，只是分支对调；没有 else 时，常量求值期间执行的是块之后的代码。
  • 与 if constexpr 不同，后者取决于常量表达式的值。
